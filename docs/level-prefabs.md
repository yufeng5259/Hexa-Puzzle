# 真实关卡数据与整块 Prefab 接入

后续进展：单关拖拽、规则及进程内保局已另批完成，见[单关可玩闭环](single-level-play.md)。本文件保留数据与展示批次的验收范围。

本批实现范围是关卡数据、页面身份与只读显示组件。沿用已有 Main、资源 scope、页面导航和正式 Prefab；拖拽、占用、判定、解锁权威、玩家存档及奖励留待后续批次。

## 数据来源与身份

工具 `tools/prefab-foundation/export-levels.mjs` 安全提取唯一原型中的 `level-data.js` 和 `mainline.js`，输出 `assets/bundles/puzzle/config/level-catalog.json`，记录两份来源文件的 SHA-256。运行时不执行网页脚本，也不依赖工作区和外部交付盘路径。

正式目录包含110道原题：80普通、30限步。96主线按五普通加一限步编排，使用全部80普通题和前16限步题；剩余14题 `mainlineNumber=null`，不进入地图和正常选关。`classic-001` 等原题ID、原pieceId、障碍、步数及目标格保持来源身份。源普通模式名 `relaxed` 显式导出为统一数据模式 `classic`，未改原ID。

`LevelDefinition` 区分题目身份和主线显示号，包含模式、局部拼块格点、目标格、障碍和可选步数。`LevelCatalog` 严格校验字段、唯一性、目标分区、形状平移及主线对应关系，再深冻结数据。offset格点转换为axial；同一纯坐标和布局函数供显示及后续命中使用，不引入玩法规则。

目录通过现有 `GardenAssetStore` 的 `dataAssets` 登记加载为 JsonAsset。启动组件持有独立目录scope；每个页面仍拥有自己的scope。目录配置归属puzzle业务包，不放到通用framework配置中。

## 选关与导航

默认地图显示1～8，可按8槽分页至89～96。分页复用已有返回箭头素材，左右按钮放在地图原关卡区下方两侧，页码放在中部；源关卡节点及底部建设／无尽入口保持原位。新增控件在原稿fixture中默认隐藏，在真实数据模式中由typed绑定启用。这是为策划中的前后段浏览新增的控件位置，需要随最终美术验收核对。

`MainlineLevelSelection` 使用明确的关号载荷选择题目；不从节点名称推断题号。普通选择范围严格为1～96。当前所有主线编号可供只读展示检查，不表示已实现玩家解锁、通关星级或存档；地图不显示伪造的通关星级。

`UIFlow` 的不可变上下文携带主线号、原题ID、地图页码和展示模式。新界面准备成功才提交选择；同题去重，不同题替换，失败与取消保留旧实例和身份。开局、局内与暂停等覆盖层使用同一身份；取消另一个题目的预览也不会改写底下原局的身份。

正常展示按模式与块数选择已有T01/T04开局和T02/T05局内版式。`FoundationBoot.preview(id,state)` 保留原稿fixture；开发专用 `previewLevel(id)` 只允许储备题，不挂产品按钮。储备预览明确显示挑战题号，不冒充第97关等主线。

## 实际 Prefab 与组件

- 每个拼图开局／局内版式预挂 `PuzzleBoardPresentation`，明确绑定真实棋盘、托盘挂点、整块和单格模板、三层几何、标题、剩余标签和总格数。
- `PuzzlePieceItem` 预挂 `PuzzlePiecePresentation`，根和触摸区域均采用中心锚点，`cellsRoot` 与原稿 `fixtureRoot` 分开。每块持有原pieceId和局部格点，子格实例化现有 `HexCellItem`。
- 真题棋盘由所选题目的目标格与障碍组成，重算木纹遮罩、边框和阴影。障碍格显式灰度显示，复用为空槽时恢复；原稿固定位置的障碍标记在真实模式隐藏。
- 托盘3块单行、4～6块三列两行、7块四列两行。按原稿托盘内区域统一缩放，完整形状同时可见，保留原木框和固定按钮。
- 普通剩余数字显示拼块数，限步显示题目moveLimit，总格进度显示 `0/目标格数`，不沿用原稿固定分母。
- 触摸组件仅发送带pieceId的start／move／end／cancel意图，不移动拼块、不占格、不改变步数或玩家数据。

原稿和真实题目是互斥展示入口。真实模式先隐藏明确绑定的fixture节点，并从 `CorePresentation` 实例化集合中排除旧样例格；仍复用原托盘母件及固定界面。整块内部也隐藏原稿样例。原稿预览则不启用真实显示根。

## 生命周期与生成所有权

组件借用页面scope，不释放另一所有者的资源。换题、隐藏和销毁使请求身份失效，迟到图片不能覆盖新题。复用时清除上一题多余的格子、拼块身份与灰度状态。

Creator可能先销毁子节点并清空其字段，再调用父组件清理。显示组件因此只调用仍有效的子组件，清理幂等；父组件不重复销毁已随子树销毁的节点。本轮针对该真实原生故障新增子先销毁回归。

绑定脚本和正式Prefab继续由原生成器管理，保持UUID与哈希保护；新增数据目录纳入同一受保护输出。展示逻辑放在独立presentation脚本，避免生成器覆盖业务实现。未恢复被删除的旧入口或资源，未新增依赖。

## 验证与阶段边界

`npm test` 包含数据、映射、布局、导航身份、迟到结果、fixture排除和生命周期回归；`npm run audit` 校验正式目录与来源逐题一致以及原有资源／Prefab契约；`npm run levels:verify-native` 复用现有Creator 3.8.8预览。

原生检查包括实际指针选择6／12／96、地图首末分页、未知／储备选择拒绝、失败保留与快速切题、四尺寸3／4／6／7块完整边界、输入只发意图、资源所有权和操作期存储零写入。7块截图使用明确标记的储备题。
