- 新增页面和缺失状态也必须延续该游戏已有正式效果图的美术风格。Block 当前以 `F:/qiguobing/git/Hexa Puzzle/Project/arts/效果预览/` 根目录现有九张效果图为风格基准；原型页面只提供功能与布局参考，不能替代美术依据。逐项核对场景透视、木纹与金色包边、花叶装饰、按钮厚度与高光、图标角色造型、配色、比例、疏密和光照，不能以“功能完整”或“使用了一部分原素材”代替整页风格一致。
- 能直接使用的现有完整素材必须优先复用，保留原材质与合理比例。不能为制作方便另画简化图标、换成扁平控件，或把原面板过度拉伸后视为风格复用。确需新增或重生的部件，应同时参照正式整页与对应母件；先在真实页面位置并排复核，通过后再制作全部状态并同步 PSD、切图、配置和预览。用户指出风格不符时，相关候选的风格结论失效，须返工复核后再发布。
- 非封面主标题文字按第五节统一去字并以微软雅黑重建；原效果图用于文字内容、用途与布局分析，不能据此保留其他设计字体或把文字烘焙进素材。
- 原效果图保留为参考源，未经用户要求不得覆盖。用户要求覆盖的是现有交付素材和 PSD 时，应在这些原交付路径修复，不要另出多套“最终版”。
- 不以截图裁片数量、输出文件数量、脚本通过或耗时作为完成依据。以素材独立可用、分层组合正确、目录唯一清楚和验收闭环为准。

## 二、先分析再拆分

- 所有页面的功能以实际程序为依据，美术、样式和布局可按用户授权发挥。核对脚本、真实 prefab 绑定、active/运行显隐、当前开关与配置，不能把存在但未启用的方法画成可用入口。区分广告成功领取与直接点击选择，完整表达品质、奖励列表及滚动、消耗、解锁、计数语义和关闭后果；发现差异同步修正相关页面及其 PSD、配置、预览和入口。源程序内部矛盾与运行阻塞如实记录，不以生成稿假装功能已接通。制作美术不表示启用入口或开发玩法。

开始制作前，检查原效果图、已有素材、PSD、索引、配置和当前最终目录，建立来源与使用关系。至少区分以下内容：

| 内容 | 制作与组织要求 |
| --- | --- |
| 公共 UI、公共道具、同图复用资源 | 建立唯一母件及稳定标识，记录所有使用页面；公共 UI 存入 `PNG/公共UI/`，公共角色、道具、商品等存入 `PNG/公共素材/`，多页引用同一个最终文件。 |
| 页面专属资源 | 存入 `PNG/页面素材/<页面>/`，其中 UI 单独存入 `UI/`；标记用途和依赖，保留正确坐标与层序，不能遗漏在公共资源或预览分类之外。 |
| 固定环境和静态装饰 | 不需要独立变化的非文字内容可合理合并，例如固定场景；封面游戏主标题的例外见第五节，不能推广为所有固定标题。 |
| 按钮、图标、可移动商品、角色、动态部件 | 按游戏操作、替换、动画及状态变化需要拆分；不能只抠出截图中露出的局部。 |
| 文字与本地化 | 先区分翻译文案、参数模板、语言相关数值格式与玩家/服务端输入；除封面游戏主标题外，内容、文字参数与图片容器全部分离，PSD 微软雅黑真文本与配置对应。 |
| 状态与交互 | 需要变化的锁、红点、开关滑块、进度填充、按钮状态、转轴部件等分开；保留状态关系、父子关系和控制参数。 |

- 不能因名称相同或外观相似就直接替换另一款素材。先确认造型、语义、状态、画布及实际使用位置匹配。
- 按用途决定合并和拆分：可以一起静态使用的内容合并；需要单独替换、显示、移动、旋转、计数或交互的内容分开。发现拆分不足，必须继续拆分。
- 装饰插画中的商品或角色可以作为静态画面合并；实际参与玩法的商品、角色和棋盘状态不能误烘焙成通用静态背景。需要实时场景截图或运行时合成的背景，必须在配置和说明中标明，不能把某一局的固定状态当成通用玩法资源。
- 裁片、完整母件和实际页面实例必须有明确映射。完整高清图替换页面裁片时，保留正确的目标框、裁剪、比例、偏移和锚点，不得直接硬拉伸。
- 图片裁紧透明边后，必须把裁掉的偏移补回实例坐标；封面主标题图片同样不能沿用裁切前左上角而整体偏位。生成图的远处极低透明度噪点不能撑大适配边界、造成主体缩小；同时不能裁掉真实阴影、柔光、细茎或半透明翼缘。以实际可见轮廓和原位对照确定目标框。

## 三、图片质量与修复

- 图片不得存在非设计所需的毛刺、锯齿、色边、白边、黑边、底色污染、碎屑、破洞、缺口、残文字、残控件或明显模糊。所有最终交付资源都要覆盖检查，包括暂未被页面引用的完整母件、预留素材和状态，不能只修用户截图圈出的几张。
- 透明图必须使用真实、正确的 alpha。检查边缘 RGB 与半透明像素，避免在深底、白底和实际场景中产生污染；不能用不透明底色或极小 alpha 藏住脏边。
- 保留设计本身的圆角、描边、高光、柔和阴影、真实孔洞和需要的细部。不能用统一阈值、整图侵蚀、强锐化或模糊来掩盖问题。
- 原设计合理的景深和柔和阴影不等于质量缺陷；低清裁图、反复缩放、拉伸纹理及粗糙抹除造成的模糊必须修复。
- 优先使用已有、匹配且已验证的最终母件。对同一资源的所有实际引用同步更新，不能只更新公共目录而留下旧页面副本，或只更新预览而不更新 PNG、PSD。
- 能用现有像素修复的局部问题优先精修；抠图无法得到完整、清晰、可用的素材时，可按用户已授权范围补绘或重新生成。新图必须匹配原设计，不能用随意设计、无关素材或简单占位图替代。
- 用户指出锯齿、模糊或缺失时，必须重新排查该游戏全部交付图片及原效果图中的应有内容，不只处理点名或圈出的局部，不以旧验收通过结论免检。逐件记录问题、采用的修复方式和当前实际保存版本的复查结果。
- 原像素无法精修到清晰、完整、独立可用时，必须按本文件及适用生图技能重新生成或参考原图补绘；不能反复放大、模糊、锐化或简化轮廓后勉强交付。生图须保留原图造型、风格、比例、色彩与细节，逐候选查看后再采用；无法保真的候选继续迭代。
- 现有素材修复或重生成后，须在其原交付文件路径覆盖，同步实际可见 PSD 图层、实例、配置及预览，不能只另交一张新图。确需新增缺失部件、完整母件或独立状态时，应新增正式图片及稳定标识，补齐用途、页面引用、坐标、层序与清单，再重新检查整页有无遗漏、重叠或重复显示。
- 重新生成的遮挡区域属于推断，不得宣称恢复了原图不可见内容，或在未经核验时宣称遮罩外像素完全不变。记录采用的最终候选、提示词、来源和必要的处理方式，过程记录放在最终目录外。
- 优先采用足够分辨率的清晰母件。高分辨率母件按实际需要一次高质量缩小；不得把低清截图放大后冒充高清，也不得为修边反复整图缩放。
- 保持已有画布、锚点、内容位置和轮廓边界，除非真实缺失、拆分或设计需要改变。必要改变必须说明并同步所有相关配置和 PSD。
- 使用已授权的本机图片接口时沿用匹配的服务配置；不能把进程环境变量为空当成没有凭据。凭据只临时注入所需子进程，不输出、不写入项目或提示词、不发往其他服务。
- 制作或重生成可本地化的底板、按钮、标牌、徽章及背景时，提示词明确要求无文字、无数字、无伪字；保留必要图标和材质，文字由独立组件配置。除已登记封面游戏主标题外，不能生成带字成图后直接交付。

## 四、背景必须整件可用

- 每张背景都必须完整打开，检查裸图原尺寸，并查看必要的放大局部。不能只检查最后被弹窗、卡片或按钮遮住的整页组合。
- 不得保留大块异景贴片、重复货架、截断的植物、半个角色、旧控件轮廓、硬矩形色块、不同清晰度的拼景、直线截断的云纹或不连续的沙地、地砖、木梁。
- 去除控件后，应恢复连续的原场景结构、透视、材质、光照、阴影和边界。局部填补仍导致背景不完整时，应继续修复或按原图重建整张背景。
- 禁止用“这个区域会被上层挡住”作为背景通过的理由，也不能把裸背景不可用的结果描述为已完成。
- 有意透明的场景部件必须有对应的独立依赖，例如建筑门洞配门层；应检查透明组合是否合理，不能把意外缺失解释成设计分层。

## 五、去字、微软雅黑与多语言

**唯一默认例外是游戏封面上展示游戏名称的主标题及其标题艺术字。** 该例外必须登记页面、资源和用途，不能扩大为所有标题、英文、标牌或装饰文字。其他中英文、数字、单位等文字全部从图片母件、页面实例和运行 PNG 中去除；不另交文字 PNG，不保留同内容的可见栅格文字层。原始参考截图可在明确标注的隐藏参考组内保留，不参与运行或正常合成。

“当前文案不变”不代表可以烘焙。制作前按下表逐项归类，不再用“固定文字可保留图片”作为例外：

| 文字类别 | 示例 | 素材、PSD 与运行配置要求 |
| --- | --- | --- |
| 需要翻译的界面文案 | 按钮、菜单、导航、页面/弹窗标题、任务说明、道具/建筑名称、教程、反馈、状态、榜单字段、奖励说明 | 图片去字；微软雅黑真实文本层；稳定本地化键、默认文案与用途，运行时按语言取词。 |
| 带数据的可翻译模板 | “关卡 {level}”“最高分 {score}”“还需 {count} 星”“{name} 的家园” | 整句模板与命名占位参数分离，允许译文调整语序；保留对应数据绑定，不能靠拼接多个中文碎片实现翻译。 |
| 语言相关的数字和格式 | 金额、数量、分数、进度、百分比、排名、日期、时长、倒计时、货币和数量缩写 | 文字组件与原始数值/格式参数独立；声明格式类型及绑定。单位、前后缀和缩写可本地化，避免把中文或特定地区格式写死为图片。 |
| 玩家或外部输入 | 玩家昵称、房间名、服务端显示名称 | 独立真实文字与数据绑定，不擅自翻译用户输入；标签与外围模板仍需本地化，检查超长内容与缺字处理。 |
| 封面游戏名称主标题 | 游戏封面主 Logo/艺术字 | 可保留原设计字形图片，逐件登记例外；若以后要求本地化该标题，另行提供对应标题资源及映射。 |

- 除上述封面主标题例外外，PSD 文字统一使用微软雅黑真实可编辑文本层，可按层级使用同字体家族的常规/粗体等字重。微软雅黑是制作要求，不是原字体不可用时的备选；不得沿用其他设计字体、轮廓字图片、像素层改名或仅隐藏真文本层。
- 图标和装饰图形按语义保留，不能把去字扩大为删除图标；但把字母、数字、文字标签称为“图标”不能免除拆字要求。
- 去字后隐藏全部独立文字，完整检查空底板原尺寸及必要放大局部。渐变、纹理、材质、光照和透明边缘须连续，无残字、双印、矩形明暗印、模糊涂抹或局部补丁；不能靠新文字遮住问题区域。
- 每个文字对象的配置包含稳定标识、类别、本地化键或数据绑定、默认值、命名占位参数及字体、字号、字重、颜色、描边、位置、显示区域、对齐、行数和溢出策略，与 PSD 当前显示内容一致。翻译文案无需因暂时无数值变化而划为图片；纯数字/玩家输入也不能伪造为待翻译句子。
- “几小时前”“第几关”“获得多少奖励”等按完整语义提供命名参数模板，不能用中文语序拼接数字、单位或碎片词条。正式接入目标语言时，按其语序、复数和单位规则配置文案变体或引擎本地化格式；中文默认模板与伪本地化检查不代表这些语言规则已实现或验收。
- 按原图的视觉层级、颜色和位置设置微软雅黑，允许为字形差异合理重排。预留译文长度与数值增长空间，明确换行、容器扩展或最小字号；不能无限缩小、横向拉伸字形或裁切来掩盖布局不足。至少验证默认中文、代表性长译文/伪本地化文案及合理数据增长，说明实际覆盖的语言范围；未提供的语言不得宣称已验证。
- 文字区域以容器内部的真实可用范围为准，避开花饰、图标和弧形边框。默认稿的文字墨迹坐标不能直接套用到不同长度的译文；运行时按安全区域、对齐、行数与字号策略重新排版，并检查装饰遮挡，不能仅凭矩形框内无溢出验收。
- 本节替代此前“固定文字可保留图片”和“原字体不可用时使用微软雅黑”的规则。历史交付的旧 PASS 不代表符合本节，处理获授权游戏时须全量清点文字、去字和重建文本后重新验收，不自动扩大到未授权游戏。
- 每张效果图对应同名 PSD，保持正确画布、图层顺序、位置、可见性、透明度和组合关系。合理分组，独立资源与动态部件必须可编辑使用。
- 不能有空图层、近乎不可见的伪素材、错位引用或错误的重复显示。隐藏参考图层须明确用途，不进入运行资源清单；隐藏参考或素材库更新不能代替实际可见图层更新。
- PNG 修复后同步 PSD 中实际使用的图层、相关母件及实例；PSD 保存后重新打开，核验真实图层、文本对象、参数和像素内容，并重新生成实际合成预览。
- 检查 PSD 实际图层合成与最终 PNG 合成的一致性，不能只检查文件头或旧缩略图。普通 8 位、正常 alpha 合成的通道舍入差默认不超过 2 级；超出应排查色彩、合成或保存错误，不能自行扩大容差掩盖差异。大型原生素材库可逐层核对像素及位置，避免为验证而强制渲染超大拼板。
- PSD/PNG 一致性只证明同步正确；是否符合原效果图必须另外做视觉对照。

```text
    页面配置/               # 每页坐标、层序、状态、图片引用、独立文字与本地化/数据参数
    素材清单.json            # 稳定标识、尺寸、用途、公共/专属属性、使用页面
  PSD/                      # 同名分层源文件及必要的完整母件库
  效果预览/                 # 每个效果图仅一份当前实际合成
  页面对照/                 # index 专用展示资料，不属于游戏导入资源
    原页面/                 # 逐页原效果图原字节副本
    PSD合成/                # 从当前实际保存 PSD 重新合成
  index.html
  使用说明.md
  交付清单与校验.json
  文件校验清单.json
```

- 最终运行 PNG 每张只保存一次。按上述真实目录区分公共 UI、公共素材和各页专属素材，清单分类及网页筛选必须与实际目录一致。不得另建一套平铺 PNG、页面缓存、高清目录或重复最终资源来兼容旧路径。
- 公共与专属按实际用途判定：多页确实复用的同一资源，以及明确面向多页的通用资源，归公共目录；仅供某一页使用的专属资源归该页。页面之间外观相似但像素、尺寸、造型或状态不同的资源不能强行当成一个公共文件。通用按钮的独立状态可放在同一公共 UI 目录下，用清单记录状态关系。
- 每页目录的 `UI/` 只放该页专属 UI，公共 UI 由页面配置引用 `PNG/公共UI/` 中的唯一文件，不复制到每个页面。公共角色、道具、商品等同理引用 `PNG/公共素材/`。非 UI 资源不得为了分目录而混入 UI；无资源的分类不必建立空目录。完整母件和页面实例有真实像素或画布差异时，保留必要的独立文件并记录适配关系，不作为重复副本删除。
- 同画布、同解码 RGBA 像素的真实重复图合并为一个最终文件，保留多个用途和资源身份的引用。不能按名字、相似外观或有损相似度误合并不同造型、颜色、状态或尺寸的资源。
- 同一完整母件仅因透明裁紧、缩放、旋转、透明度或九宫格实例适配而产生的副本，应逐实例验证可精确还原后合并为唯一 PNG，以参数表达差异；不能只做同尺寸文件去重就宣称资源已充分复用。记录源裁剪、适配顺序、位置补偿、稳定标识和别名。不同等级、造型、材质及必要状态继续独立保存。
- 蜂巢棋盘等由关卡数据决定的形状，采用公共木纹、木框截面、单格凹槽与棋子母件，加格子坐标、内孔、边界和布局参数生成。运行组件在内存缓存生成结果，不逐关交付木底、描边、投影或整组棋块的形状 PNG；须提供可运行重建代码、材料引用和样例数据，并与页面实际效果核对。编辑 PSD 可保存该参数化组件的实际渲染图层，不能把编辑缓存计为独立运行素材。
- PSD 的实际可见图片层须从最终目录唯一 PNG 经过已记录的实例变换，或从这些 PNG 与已交付参数化组件重建；保存后重新打开核对每层像素、位置、透明度和文字。不能使用未交付的临时裁片拼 PSD，再把不一致的其他母件交给开发。
- 页面效果 PSD 与升级／素材设计板分别归档。页面对照左侧须为对应的真实整页效果设计图，右侧为同画布实际保存 PSD 的合成图；功能原型可单独折叠标注，不能冒充效果图。升级、棋子等素材拼板使用独立“素材设计板”入口及目录，不计入页面数量，不用整页效果图与其左右假对照。
- 所有最终可用素材必须列入统一清单，包括公共资源、页面专属资源及确实需要的独立状态；不允许入口只展示某个页面分类，让用户误认为那就是全部素材。
- 页面配置使用相对于 `游戏素材/` 的可移植路径，例如 `PNG/公共UI/关闭按钮.png`、`PNG/页面素材/P1/UI/关卡按钮.png`，保留层序、坐标、尺寸、比例、透明边界适配、状态、父子关系、交互、锚点和转轴等必要信息。公共图片通过配置重复引用，不重复存图。清单记录物理归属、使用页面和资源身份；不能因挪动目录就改变稳定标识或丢失用途映射。
- `PSD/` 用于编辑，`效果预览/` 用于核对；游戏项目只导入 `游戏素材/`。说明文件必须明确三者用途，让用户能直接判断哪些文件可用于游戏。
- 原始工作参考、切片缓存、候选、失败稿、检查对照拼图、检查记录、备份、旧分类和过程报告放在 `制作检查/` 等最终目录之外，不混入最终包。唯一展示用途例外是下条要求的 `页面对照/` 原页面和 PSD 合成图，须与运行素材明确隔离。历史压缩包或过程导出不替代登记的权威目录；未经要求不额外生成重复最终包。
- `index.html` 必须独立放在本游戏最终目录中，默认展示全部最终 PNG。明确提供公共 UI、公共素材及各页面专属素材分类，页面视图同时列出该页引用的公共资源，不能让用户误以为页面目录内包含了该页全部依赖。支持按页面或用途筛选、搜索、原尺寸与放大查看，以及深底、白底、棋盘底核查；链接直接对应本目录实际文件。
- **所有新建或更新的游戏交付 `index.html` 均必须有逐页原图与 PSD 效果对照入口。** 每页同时显示“原页面效果图”和“PSD 合成效果图”，明确左右标签、页面名称与对应实际 PSD 链接，使用一致的展示比例、完整画面且不裁切，支持两图分别原尺寸及放大检查。页面筛选同步作用于对照视图；不得只提供原图下载链接或只显示单张合成预览。
- **选择具体页面后，使用同一视图上下排列：上方为该页原图 / PSD 合成图对照，下方为该页素材。** 下方包含页面专属素材和该页实际引用的公共资源，明确标注数量与范围；分类和搜索筛选作用于下方素材，不应隐藏已经选定页面的上方对照。不能把对照和页面素材做成必须来回切换的互斥模式；默认“全部素材”仍完整列出全部运行图片。
- PSD 合成图必须从本次实际保存的 PSD 重新打开，按实际可见图层重新合成；不能用原图、旧稿、候选 PNG 或仅 PSD 内嵌旧缩略图冒充。记录原图、实际 PSD、合成图的路径与 SHA，并在 PSD 修改后同步重生成。对照资料放在独立 `页面对照/` 中，原页面保存原字节副本，网页只用相对路径；不依赖项目外绝对路径，不混入 `游戏素材/PNG/` 或重复计作运行素材。整份交付目录移动后应仍能查看对照。
- 图片变化后同步入口版本标记、清单、校验和预览，防止缓存继续展示旧图。最终目录内不能残留仍被误认为可用的旧页面素材、旧公共目录或重复版本。
- 现有平铺目录迁移到上述结构时，按已授权范围先在最终目录外备份并核验，建立旧路径到新路径的映射，同步全部页面配置、清单、入口链接、文件校验及涉及的 PSD 外链。核验 PNG 字节、解码像素和实际页面效果未被目录调整改变，所有新引用均可解析，再退役已确认的旧受管理文件，不能通过保留双份文件掩盖遗漏引用。

## 七、覆盖与同步安全

- 覆盖前确认当前源、最终候选、已有文件和来源映射，建立目录外可回溯备份并核对 SHA-256。不要在版本不明、并发修改未处理或备份不一致时盲目覆盖。
- 同步范围包括所有实际依赖：运行 PNG、必要页面实例、PSD 实际图层、母件、配置、清单、文件校验、效果预览和入口。不得因某个目录已有清晰图就跳过实际引用目录的检查。
- 只修改授权游戏和任务范围，避免共享索引更新误改其他游戏或恢复暂停工作。
- 清理重复版本时，仅退役已确认归属、内容已核验且有备份的旧交付文件；不得递归清空整个项目或删除原效果图。未识别文件先保留并查明用途。
- Windows 目录被占用时，不擅自结束用户应用。可采用备份核验后的逐文件临时写入、原子覆盖及受管理旧文件退役，保持固定最终路径；完成后检查没有临时文件或旧分类残留。
- 出现中途失败，依据备份、日志和当前文件校验恢复或续行，不能反复执行只适用于修改前状态的覆盖脚本。

## 八、验收流程与完成门槛

依次完成以下阶段，前一阶段发现的问题必须闭环后再进入后续发布：

1. **清点与分析**：建立原效果图、全部最终资源、静动态分类、公共复用和文字覆盖清单；逐项归类可翻译文案、模板、数字格式与玩家输入，登记封面主标题例外，不能遗漏按钮等原先所谓固定文字。
2. **素材逐件视觉检查**：完整查看每件最终交付资源的原尺寸，在白底和深底检查透明边缘，必要时补棋盘底及 200%／400% 局部。背景额外整幅裸图检查；缩略总览只能辅助定位，不能代替逐件验收。
3. **候选修复复核**：核对完整素材、改变区域、邻接区域及实际原位组合，与原效果图相同位置对照。重要修复应由独立复核者实际查看；不把作者自查写成独立验收。候选通过只代表候选，不代表已覆盖或 PSD 已同步。
4. **保存与同步**：核对候选和源文件后覆盖对应交付文件，同步 PSD、参数及实际合成。重新打开保存后的 PSD，验证真实文本层和图层像素，并检查实际层合成。
5. **实际保存页复查**：从实际保存文件重新制作原图对照，逐页检查构图、遮挡、层序、比例、边缘及重复图。隐藏所有非封面主标题文字后检查空底板，再核对微软雅黑真实文本、本地化键/数据绑定、默认与长译文布局以及重复烘焙，不能只审候选截图。
   特别核对替换母件后文字是否仍在真实空容器内，进度填充是否与数值一致，持物的手与物件、花茎与容器、吊绳与牌等接合关系是否完整；原图存在的附属件不能因重绘主体而消失。
6. **统一导出与目录检查**：从通过复查的源导出唯一运行文件，检查公共 UI、公共素材和每页专属 UI 等实际目录归属，核对分类与使用页面；检查跨目录去重、图片解码、相对路径、逐页依赖、稳定标识、动态参数和文件 SHA。核对运行 PNG、PSD 和预览均为该版，清除最终目录内旧分类及临时内容。
7. **固定最终路径复验**：在正式最终目录实际打开 `index.html`，检查全部图片、所有页面原图与 PSD 合成图的并排对照、标签对应关系、筛选、搜索、底色和原尺寸/放大切换及实际 PSD 链接。核对对照原图原字节和实际 PSD/合成图版本，移动目录后相对链接仍可用。暂存目录通过不能代替固定最终路径检查。
8. **完成报告**：说明实际修复与交付位置、游戏应导入的目录、实际数量、完成的验证及仍存在的真实限制。只有当前任务范围的问题闭环且当前最终文件通过检查，才能宣布完成。

检查记录必须区分：技术通过、美术视觉通过、候选通过、实际保存文件通过、最终目录通过。技术检查、图片加载、SHA 一致或 PSD 文件头有效，均不能单独证明美术质量合格。

视觉结论必须绑定实际检查的源文件、PNG、PSD、预览、配置和证据版本，至少记录必要路径与 SHA；不得复制旧 PASS 或把旧稿检查结果移植给新稿。未修改内容仅在相关像素、参数及依赖 SHA 均核对未变时继承本轮检查，发生变化的内容必须重新检查。

不得把完全透明像素里的隐藏 RGB 当作真实可见毛边；应以真实 alpha 在不同底色上的合成为依据。相反，可见半透明色边、错误低 alpha 残片和引擎采样导致的污染不能忽略。

如果没有实际执行 Photoshop 交互或游戏引擎导入，应如实区分已完成的 PSD 解析、图层回读、合成验证与未执行的实机行为，不能声称已经完成未做的验证。

## 九、每次交付前自检

- 所有最终交付素材都已检查，用户指出的问题和检查中新发现的问题都已修复。
- 对锯齿、模糊、缺失的返修已覆盖全部资源和原图应有部件；无法精修的已按规则重生成，必要新增图片已接入实际页面，所有替换均已在原交付路径覆盖并复查。
- 公共资源和页面专属资源都有明确用途；文字已按多语言和运行数据分类，按钮等文案没有以“固定”为由烘焙。
- 独立素材和完整裸背景均可用，不依靠上层遮挡隐藏缺陷。
- 除已登记封面主标题外，图片素材无文字；PSD 全部文字为微软雅黑真实文本层，本地化键、默认值、参数及数据绑定完整，并已验证长译文与数值增长。
- 同名 PSD、全部独立文字、配置及实际预览已同步并回读验证。
- 每页实际组合已与原效果图对照，改变过的实际保存文件有本轮复查证据。
- 最终游戏 PNG 每张只有一份，公共 UI 与各页面 UI 已按实际目录分开，非 UI 素材归属清楚；全部在统一入口中可找到，公共依赖可追溯，配置引用完整可移植。
- 唯一最终目录没有旧稿、重复分类、候选、缓存、临时文件或检查材料混入。
- 正式路径浏览器及必要技术验证通过，报告未夸大为 Photoshop 或引擎实机验收。
- 没有当前任务范围内的待修缺陷或未完成必要检查；否则继续处理，不宣布完成。
