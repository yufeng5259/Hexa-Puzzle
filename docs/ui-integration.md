# 核心界面接入：导航、动态展示与验收边界

本轮把已制作的正式 Prefab 接入单一 `Main.scene`，完成核心界面导航、展示数据绑定和部分重复单元实例化。目标是让界面可以真实打开、返回和替换展示数据；没有实现玩家存档、关卡规则、奖励、广告或花蜜经济。

本文按当前 `app/UIFlow.ts`、`app/FoundationBoot.ts`、`features/presentation/` 及 `tools/prefab-foundation/core-ui.mjs` 的实际实现记录。原型唯一目录仍是工作区 `prototype/`；本轮临时报告、调试截图和源配置盘点统一放在 `tmp/prototype/ui-integration/`。未建立第二套原型或更换原型端口。

## 导航与输入处理

`UIFlow` 管理一个页面和覆盖层栈。新页面先准备资源，成功后才替换旧页面；准备失败保留已有页面并显示可重试提示。打开下一覆盖层时隐藏上一覆盖层，关闭后恢复上一层。页面切换关闭已有覆盖层，销毁入口取消未完成导航。

当前顶层界面才可以处理动作。已经隐藏、关闭或被覆盖的界面不能继续触发导航；连续点击以新的请求身份取消旧请求，迟到结果不覆盖新页面。显示／隐藏使用对称订阅，避免重复打开后叠加 `view-action` 监听。

固定按钮使用 Prefab 序列化 `ClickEvent` 绑定组件的 `onAction`，数据来自 `core-actions.json`。同名按钮在生成阶段按原稿 occurrence 分别绑定，不在运行时扫描节点名称找按钮。帮助目录的三个“看图学习”以及设置的五个开关不能合并成一个无上下文的事件。

返回行为是界面上下文行为：覆盖层优先关闭自身并恢复下层；拼图页面直接返回时打开退出确认；地图和 Loading 的无效返回只提示当前状态。相册、蜂友、任务等后续入口没有在本轮扩展为真实业务页面。

替换为正式 item 的旧源节点会停用，并从原稿动态资源绑定中排除，避免旧图和新实例同时绘制或重复加载。固定挂点保留原稿位置与层序；不是在运行时拼装整页固定 UI。

## 展示数据与版式字段

每个版式根预挂 `CorePresentation`，页面根通过 `PresentationGroup.layouts` 绑定这些展示组件。页面选择 `stateId` 后，只对当前启用的版式调用展示更新。

View 的字段按版式保存具体类型的绑定数组。`selectState()` 在切换根节点时同步切换当前 `Label`、`Button`、`ProgressBar` 和容器引用，避免页面换成 T05 或 T15 后仍修改第一个版式的隐藏节点。缺引用、数组长度不符或未知 `stateId` 都明确报错。

`CorePresentationData` 支持页面文字／进度值及 item 数据覆盖；`PresentationData` 支持主体、转子、装饰图的注册 assetId，文字、进度、盒子和字号。默认值、版式预览夹具与调用方覆盖按明确顺序合并；这些都是展示数据，不是第二套存档。

`PresentationItem` 缓存正式 Prefab 的默认图和盒子。省略图片字段时恢复默认值，显式 `null` 清空图片；重复展示不会残留上一个数据项的转子、图标、尺寸或字号。值校验在写入前进行，进度值必须在 0～1 范围。

本轮部分 HUD 使用固定预览花蜜与提示库存，地图体力文字按展示需求覆盖为“∞／畅玩”。家园等级、价格以及各关卡样例不构成真实余额、价格表、通关或奖励；未完成的文案和资产状态仍需随后续业务与美术验收逐项核对。

## 资源所有权与异步更新

`GardenAssetStore` 继续作为原稿、派生资源和 Prefab 注册边界。页面准备时创建自己的 `ResourceScope`，加载 Prefab 和相关图片；资源不得通过未登记路径绕过来源 manifest。

页面／ViewHost 持有 scope，展示组件只借用它；启动组件另持有关卡目录scope。`PresentationItem.present(scope)` 用注册 ID 加载 `SpriteFrame`，不创建全局图片缓存，也不自行释放另一页面的资源。动态 item 的 Prefab 引用在正式页面中序列化绑定，页面资源所有权覆盖其使用生命周期。

关闭页面时先销毁所属节点，再释放 scope；启动登记文档由启动组件单独持有并在销毁后对称释放。导航取消、页面销毁、item 隐藏／重绑都会使旧请求身份失效，迟到图片不得写入已经隐藏、销毁或更新过的数据项。重复调用清理保持幂等。

## 本轮明确没有接入的行为

未接入的签到、纪录、蜂友、活动、相册、补给、广告、存档等按钮只显示 `notice`，不冒充已成功执行。设置五个开关目前也只提示，尚未改变音乐、音效、震动、动效或大字设置。

拼图的“提示轮廓”和“取回拼块”只显示预览说明，不扣道具、不改变真实对局、不写存档。原型中的 `return-piece` 是取回选中已放拼块或最后放下的拼块；这里没有把它实现为通用历史撤销。建设和教学演示按钮同样不扣花蜜。

DEBUG 标记是开发专用入口。在拼图页面、没有覆盖层时，可以点“界面预览 · 点此演示结算”进入结算样式；发布构建不提供该结算入口。结算展示标明演示数据，奖励显示 `+0`，不发奖、不记通关、不解锁下一关。“下一关”只打开开局样式，不能当作关卡推进已完成。

退出确认不会执行真实存档；重开确认关闭当前确认并提示未重开真实对局。原稿中“保存并返回”等文字只是沿用的界面样式，真实能力边界以提示和本文为准。

## 几何渲染与美术验收

本轮 `SourceGeometry` 已从仅有挂点推进到实际几何展示：按 `block.hex.v1` 的轴坐标和裁切参数生成凹槽／障碍、异形地板、外轮廓、边框、阴影和提示描边。图形组件、Mask 与纹理 Sprite 均预挂并绑定，不在组件运行时补建整页节点树。

地板使用遮罩裁切平铺纹理，外边界通过消去共享边计算，避免每格重复画内边。原稿裁切、翻转和布局参数参与映射；水车转子仍是独立静态展示，没有接入投影旋转动画。

**几何与节点检查不等于像素一致。** 当前高光、边框着色、阴影宽度／透明度、木纹采样和连接处与原稿离线渲染仍可能存在差异。需要用 Creator 实屏与原稿逐页检查纹理、层序、文字、位置和小屏表现；不能用功能测试或主观评分代替美术验收。
