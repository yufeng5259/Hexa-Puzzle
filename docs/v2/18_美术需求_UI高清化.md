# 蜂巢小镇 v2 · 美术需求 P2-13：通用 UI 2 倍高清化（交给 Codex 执行）

更新：2026-11-18。执行方：另一台电脑上的 Codex。使用方：Cocos 程序（Creator 3.8.8，设计分辨率 853×1844）。
规范与 [03_美术切图任务.md](03_美术切图任务.md) 第 3 节相同，下面只写差异。

## 0. 一句话目标

把 P0/P1 交付的 1 倍通用 UI 切图（按钮、面板、胶囊、进度条、列表行、开关等）按**原造型、原配色**重画成 **2 倍画布**，让它们在 1440p 手机上不发虚；同时修两张有瑕疵的图。共 **77 张** PNG，覆盖同名文件。

## 1. 程序现状（为什么要）

- 2026-11-18 程序做了一次全界面审计和 Pixel 2 真机巡检。变形、九宫格挤压等问题程序已经修完（自动九宫格、按原比例放置、防变形测试）。
- 剩下的问题只能靠美术解决：**分辨率不够**。P0/P1 的切图大多是 1 倍图。按设计分辨率换算，同一张图在屏幕上的放大倍数：
  - Pixel 2（1080×1920）：约 1.25 倍，圆角和描边开始发软；
  - 主流 1440p 手机（1440×2560）：约 1.7 倍，按钮圆头、面板描边明显发虚；
  - 无尽活动页“开始挑战”这类大按钮：最高约 3 倍。
- 按审计结果，在 1440p 上放大超过 1.5 倍的切图有 57 张（同一套图的多个状态算 1 张）。本批把这些图连同它们的其他状态一起重画为 2 倍，共 77 个文件。
- **为什么复用不够**：这些是原图本身像素不够，换用别的切图也一样会发虚，只能按原造型重画为 2 倍。
- 不在本批：全屏背景（`bg_loading`、`bg_puzzle`、地图背景）是绘画质感，轻微发软可以接受；角色和已经是 2 倍的图标（P2-5～P2-12）。
- 程序已支持 2 倍九宫格：清单里写 `scale: 2`、九宫格边距按 2 倍像素填写，程序按实际像素排版，显示尺寸不变。

## 2. 共同要求

1. **画布正好是现有画布的 2 倍**（见第 3 节“2 倍画布”列），构图、比例、造型、配色、明暗、描边粗细（按比例）都与现图一致。只提高精度，不改设计。叠放对比时，缩小一半后与原图轮廓偏差不超过 1px。
2. **九宫格边距按 2 倍填写**（第 3 节“九宫格（2 倍）”列）：四个角和边框完整落在边距以内；中间可拉伸区域必须是平整的纯色或均匀渐变，不能有高光点、纹理或装饰（会被拉伸）。
3. **同一套的多个状态画布相同、轮廓重合**（normal/pressed/disabled、on/off、reached/unreached 等），程序运行时直接换图。
4. 外轮廓有 2–3 像素（2 倍下）的半透明过渡，半透明像素取图形自身的边缘色，不带白、米色、黑或原背景色。
5. 在 4 种底色上都干净：白 `#FFFFFF`、米色 `#F6EBD2`、深蓝 `#0E2A5C`、草绿 `#7CC44E`。
6. 不含文字和数字。

## 4. 交付清单登记

更新 `美术交付清单.json` 中对应的 `uiAssets` 条目（不要新建 id），写 `batch: "P2-13"`：

1. `size` 改为 2 倍画布尺寸，`scale: 2`（写法同 P2-7）。
2. 有九宫格的写 `slice`，填 2 倍像素值，顺序与现有条目一致：`[左, 上, 右, 下]`。
3. `source` 写“P2-13 2 倍重绘：原造型配色，边缘抗锯齿”，`task_icon_puzzle` 写“P2-13 去残影”；更新每个状态的 `sha256`。
4. `priority` 不变。

## 5. 对照图

放 `制作记录/补充YYYYMMDD/对照/`：

1. **新旧对比**：每张新图缩小一半后与旧图并排，4 种底色各一行；再加一张 3 倍最近邻局部放大（圆角、描边）。按 A、B、C 三档分 3 张总图。
2. **九宫格拉伸检查**：每张九宫格图按第 3 节“1 倍显示”的尺寸拉伸一次（按钮拉到 568×105 和 595×166，面板拉到 712×857，列表行拉到 760×124，进度条拉到 420×42），确认四角不变形、中间区域平整。
3. **多状态叠放**：同一套的状态半透明叠在一起，证明轮廓重合。

## 6. 验收标准

1. 77 个文件路径不变、画布正好是原画布的 2 倍；缩小一半后与原图轮廓偏差不超过 1px，配色一致。
2. 九宫格边距与第 3 节一致；四角和边框都在边距内，中间区域平整无装饰。
3. 多状态画布相同、轮廓重合。
4. 4 种底色无白边、残边；3 倍放大无台阶状锯齿；`task_icon_puzzle` 无残影，`divider_gold` 有半透明过渡。
5. 清单登记符合第 4 节，SHA 匹配。

## 8. 交付后程序侧会做什么

1. 运行 `node tools/v2/import-art.mjs --run` 导入，`node tools/v2/build-ui.mjs --run` 重新生成 Prefab。程序按图片实际像素排版九宫格和胶囊按钮，显示尺寸不变。
2. 运行防变形测试，以及在 1440p 换算下的清晰度审计，确认 77 张不再超过 1.5 倍放大。
3. 用 `npm run build:apk` 打包到 Pixel 2，逐页巡检（原分辨率加长屏模拟），重点看按钮圆头、弹窗描边和开关。有问题在本文件末尾追加“问题反馈”。

## 问题反馈

### 2026-11-19：1440p 长屏下胶囊圆头的清晰度边界

P2-13 的 77 张交付保持原尺寸约定（76 张翻倍、任务图标 264×264 不变），Logo 原字标及签到/无尽的状态轮廓差异保留。当前 S19“开始挑战”按钮显示高 166，胶囊原图高 184，圆头在 1440×3200 下实际放大约 `166/184×1440/853 = 1.525` 倍，略超第 8 节 1.5 倍门槛；1440×2560 下约为 1.254 倍。九宫格中部的有意拉伸不计作圆头清晰度倍率。

本轮按用户最新要求仅处理美术，不改程序或布局，也不擅自扩大已明确的 2 倍画布。该项保留为后续程序/美术协调的边界问题，不宣称全部 1440p 场景通过。逐张美术复核见本批[验收记录](制作记录/补充20261118/P2-13/验收记录.md)。
