## 4. 存档 v2

新键 `honey-town.v2`。一次写入整份状态，写成功才算交易完成；所有交易带唯一凭据 ID，防止重复发放。

```
GameStateV2
  schemaVersion: 2, revision
  wallet: { coins, hints }
  energy: { value, nextRecoverAt }
  player: { level, exp, pendingLevelUpDisplay[] }
  mainline: { nextLevelNo, firstClearDone{levelNo:true}, activeAttempt|null }
  maps: { currentMapId, buildings{mapId:{buildingId:level}}, completedMaps{}, completionClaimed{} }
  pendingBuild: { buildId, mapId, buildingId, fromLevel, toLevel, paidCost, status } | null
  rewardQueue: [ 待展示的奖励记录 ]
  signIn: { claimedCount, lastClaimDay }
  daily: { day, tasks[{type, target, progress, claimed}], chestClaimed }
  endless: { unlocked, best, week{ weekId, score, claimedStages[] }, activeGame|null }
  guide: { stepId, completed }
  settings: { music, sound, vibration }
  receipts: { [凭据ID]: true }
```

- 建造两段式：接单（扣费 + 写入 `pendingBuild`）→ 播施工动画 → 落成（等级+1、经验、奖励、清空 `pendingBuild`）。启动时发现 `pendingBuild` 未完成，就补播施工并落成，不再收费。
- 无尽对局整盘保存（棋盘、本批剩余拼块、单局分），读档不重新抽牌。
- 日期：本地自然日和周一 0 点，统一由一个 `Clock` 服务给出 `dayId`、`weekId`，方便测试时注入时间。

    hud/                     顶部资源栏

## 7. 验证

- `core/` 每个模块都有 node 单测，覆盖策划第 14 节 V01–V16 中能用逻辑验证的部分：重复点击不重复扣费/发奖、保存失败不改状态、施工中强退可补完、跨日/跨周、无尽多线交叉和结束判定等。
- 拼图回归：110 题身份和顺序、放置/取回/计步规则与当前一致。
- 每个阶段结束时在 Creator 预览里实际操作对应页面。
- 美术到位后，用布局 JSON 核对 Prefab 位置，并和效果图截图对照。

## 8. 风险与注意

- **体力规则变更**：现在是失败、放弃、重开时扣，v2 改成开局扣。要连同重玩、复玩、恢复旧局一起改，避免重复扣或漏扣。
- **建造时序**：现在是先存新等级再播表现；v2 是动画播完才显示新等级，依赖 `pendingBuild` 恢复。
- **无尽发牌**：要保证每批至少有一块能放下，又不能每次都放得下；权重需要试玩调整，先做成可配置。
- **美术未到**：程序先用纯色占位图搭 Prefab，节点名与切图 ID 一致，到图后只换贴图。
- **字体**：效果图用的微软雅黑不能打包，先用系统默认字体，后续另选可商用字体。
