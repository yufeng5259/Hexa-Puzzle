# 蜂巢小镇 v2 · 无尽排行榜（蜂群联赛）与拼图胜利弹窗设计

更新：2026-11-17。状态：用户已确认，待实施。对应美术需求：[17_美术需求_排行榜头像与胜利弹窗.md](17_美术需求_排行榜头像与胜利弹窗.md)（P2-12）。参考截图：`docs/猫咪数独/`、`docs/蜜蜂修改建议/需要改成结算弹窗.png`。

## 0. 一句话

无尽活动加“每日 / 每周 / 总榜”三个页签的排行榜。对手全部是本地模拟选手（机器人），数据存本地，暂不做服务器，但通过 `LeaderboardService` 接口预留服务器接入。每日联赛按名次发奖并加星，星满升段（5 段，只升不降）。拼图胜利改为居中结算弹窗。

## 2. 参考数据（成熟游戏）

| 游戏/活动 | 人数 | 周期 | 奖励 |

| Toon Blast「Star Tournament」 | 50 | 约 2 天 | 1000/500/250 金币（1 : 0.5 : 0.25），第 4–10 名 3 把锤子，第 11–50 名无 |
| Toon Blast「Weekly Contest」 | 10 | 每周 | 只奖前 3 |
| Duolingo 联赛 | 30 | 每周 | 10 段，靠升降段驱动，无物品奖 |
| 猫咪数独（截图） | 约 20 | 每日 | 前三领奖台，加 20/15/10 星，星满升段；次日弹结算 |

规律：小组（20–30 人）才让人觉得第一名够得着；只奖前 10；前三名大致按 1 : 0.6 : 0.4 递减；4–10 名给少量道具。Royal Match 买 5 步要 900 金币，第 1 名的奖励约等于 5 次续关：值得冲，但不破坏经济。

## 3. 三个页签

| 页签 | 排什么 | 组规模 | 周期与重置 | 奖励 |
|---|---|---|---|---|
| 每日联赛 | 当天无尽**新增分**（与周积分同口径：每次有效放置增量） | 20（19 机器人＋自己） | 本地日期，0 点重置（同每日任务） | 按名次发奖＋加星 |
| 每周榜 | 本周累计分（即现有 `endless.weekScore`） | 30（29＋自己） | 周一本地 0 点（同现有周积分） | 前 10 名发奖；现有周积分阶段奖励保留 |
| 总榜 | 单局历史最高分（现有 `endless.best`） | 100（99＋自己） | 不重置 | 无 |

- 每日和每周：当期分数大于 0 才进入排名和结算；分数为 0 时显示组和机器人，“我”这一行显示“打一局即可参赛”。
- 同分时，先达到该分数者在前；玩家与机器人同分，玩家在前。
- 无尽解锁前（`endlessUnlockAfterLevelNo`）排行榜入口跟着隐藏。

### 4.4 经济影响

普通玩家每天约多 20–60 金币，相当于每日任务（160）的 15%–35%；每周榜奖励约等于 1–5 次通关。提示控制在每天最多 1 个，避免拼图难度被稀释。数值由 30 图经济模拟（14 文档 4.2）统一复核。

## 5. 机器人

### 5.1 机器人表 `LeagueBots`（约 120 行）

| 列 | 类型 | 说明 |
|---|---|---|
| id | string | `bot001`… |
| nameZh | string | 昵称，蜂蜜词＋动物，与头像一致，如“蜜糖熊”“花粉兔”“嗡嗡狐”“蜂蜡小猫”“甜甜熊猫” |
| nameEn | string | 预留本地化，如 Honey Bear；本轮不显示 |
| avatarId | string | 24 种动物之一（见 17 文档），如 `avatar_bear` |
| avatarBg | int | 头像底色 0–5（程序着色） |
| style | enum | `casual` 零散；`steady` 均匀；`sprinter` 期末冲刺；`nightOwl` 夜间 |
| skill | number | 0.3–2.0，决定在组内的强弱排序 |
| sessionsMin / sessionsMax | int | 每天活跃段数，2–5 |
| activeFrom / activeTo | int | 活跃小时，如 8 / 23 |
| sprintShare | number | 冲刺型在最后 3 小时完成的分数比例，0–0.5 |
| tierMin / tierMax | int | 出现在哪些段位 |

同一动物可对应多个昵称（24 头像 × 约 5 个昵称）。

### 5.2 建组（每期一次，写入存档后不再改）

1. 种子＝hash(玩家 ID, 页签, 周期 ID, 段位)。玩家 ID 为首次启动生成的随机串（存档内，不上传）。
2. 从 `LeagueBots` 按段位筛出候选，不重复地抽 19 / 29 / 99 个，按 `skill` 从高到低排序。
3. 每个机器人分配目标分：`target_i = B × curve_i × strength × jitter`，jitter 在 0.9–1.1 之间随机；然后在活跃时段内随机生成若干段（每段 10–40 分钟），把目标分按随机比例分到各段，冲刺型把 `sprintShare` 放进最后 3 小时。
4. 基准分 B：
   - 每日：玩家最近 7 个有分日的每日分中位数，不低于段位 floor；新玩家用 `leagueDailyBaseDefault`（800）。
   - 每周：最近 4 周的周分中位数，不低于 floor×5；默认 `leagueWeeklyBaseDefault`（4000）。
5. 名次曲线 `curve`（`LeagueCurves` 表，每日 19 项）默认：1.50, 1.30, 1.15, 1.00, 0.92, 0.85, 0.78, 0.72, 0.66, 0.60, 0.54, 0.48, 0.42, 0.36, 0.30, 0.25, 0.20, 0.15, 0.10。每周 29 项同形状插值。
   - 效果：在工蜂段，正常发挥（B）大约第 4 名，多打一两局可进前三，拿第一需要约 1.5 倍投入。段位越高，同样努力排名越靠后。
6. 总榜：首次打开时生成 99 个机器人，最高分在 `leagueAllTimeMin`（300）到 `leagueAllTimeMax`（30000）之间按对数均匀分布；每周一按 1%–3% 随机上涨一次（种子同上），上限 ×1.5。

### 5.3 分数随时间计算

机器人在时刻 t 的分数＝Σ 各活跃段已完成部分（段内线性增长），按 5 分取整。存档只存参数，打开时现算。好处：

- 同一时刻多次打开结果一致；离线回来能看到合理增长。
- 跳到期末直接得到最终分，改时钟往前没有好处。

建组后**不再**根据玩家表现调整机器人，避免出现“我加分它跟着加”的感觉。

### 5.4 透明度（Google Play 欺骗行为政策）

- 规则说明页写明：“蜂群联赛的对手是模拟选手，名次和奖励只和你自己的成绩有关。”
- 不显示“在线中”“正在游戏”“x 分钟前”等真人状态。
- 昵称使用明显的虚拟角色名，不伪装成真人 ID。

## 6. 结算与领奖

1. **检测**：启动、回前台、进主页或无尽页时，检查当期 ID。若存档里的每日组或每周组已经过期，且我的分数大于 0：用期末时刻算出全部机器人最终分，确定名次，生成待领结算 `{id: "daily:2026-11-17", board, rank, rewardId, stars, tierBefore}` 并保存。最多保留 7 条，过期的丢弃。
2. **展示**（S27 联赛结算）：
   1. 名次与标题（“昨日第 2 名”“你已获得第一名 N 次”）；
   2. 有礼盒就先抖再开，奖励卡逐项飞入（复用奖励播放器）；
   3. 星星飞入段位进度条；升段时出现新段位徽章。
   多条结算按时间顺序合并成一次弹窗，翻页显示，不连续堆叠。
3. **交易**：领取＝发奖＋加星＋升段＋写凭据（`league:<id>`），一次保存；保存成功才播放到账。保存失败保留待领，可重试。凭据防止重复领取。
4. **时钟**：沿用现有时钟防回拨；检测到回拨时不生成新结算，也不重置当期组。
5. 不设领奖时限（7 条以内）；不做双倍领取（本轮无广告）。

## 7. 存档（State 新增 `leaderboard`）

```ts
leaderboard: {
  playerId: string;
  tier: number; stars: number; firstPlaceCount: number;
  daily:   BoardGroup | null;   // 当期组
  weekly:  BoardGroup | null;
  allTime: { createdAt: number; bots: BotEntry[]; lastGrowWeek: string } | null;
  history: { daily: number[]; weekly: number[] };   // 用于基准分 B，最多 7 / 4 条
  pending: Settlement[];        // 待领结算
}
BoardGroup = { periodId: string; tier: number; base: number; myScore: number; myReachedAt: number; bots: BotEntry[] }
BotEntry   = { botId: string; target: number; sessions: [startMs, endMs, share][] }
```

- `myScore` 在无尽每次有效放置时随周积分同一次保存增量，不另起交易。
- 不兼容旧存档（v2 规则），新档默认值：tier 1、stars 0。

## 8. 预留接口

```ts
interface LeaderboardService {
  getBoard(tab: 'daily' | 'weekly' | 'allTime', now: number): Promise<BoardView>;
  reportScore(delta: number, best: number, now: number): Promise<void>;
  getPendingSettlements(now: number): Promise<Settlement[]>;
  claimSettlement(id: string): Promise<ClaimResult>;
}
BoardView = { tab; periodId; endsAt: number | null; tier; stars; starsToNext; rows: Row[]; me: Row; joined: boolean }
Row = { rank; name; avatarId; avatarBg; score; rewardPreview?: RewardView; isMe: boolean }
```

- 第一版只实现 `LocalLeaderboardService`：规则为纯函数（`core/League.ts`），只依赖配置、存档和时钟，可单测。
- 界面、结算弹窗、发奖只依赖这个接口。以后接服务器时换成 `RemoteLeaderboardService`：服务端校验分数、下发结算凭据，UI 与配置不改。
- 接口全部异步，界面要处理加载中和失败，这样接服务器时不用返工。

## 12. 验收要点

1. 同一时刻反复打开，榜单完全一致；离线 3 小时后机器人分数有合理增长。
2. 工蜂段用默认基准分模拟：玩家打出 B 时排第 3–5 名；打出 1.6B 时有较大概率第 1 名。
3. 跨天结算只出现一次，领取一次；改时钟回拨不出结算；多日未登录合并展示。
