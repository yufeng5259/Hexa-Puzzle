更新：2026-11-16（程序评审重写）。评审对象：[09 详细设计](09_交互需求_奖励动效与结算.md)（`be331a6`、`21719c4`）。代码基线：`ab4f217` 加 2026-11-14 的可读性/顶栏改版（弹窗随屏放大、最小点击区与字号、分开的顶栏胶囊；待用户确认后提交）。

状态：评审完成，09 已按下文修订；所有动画、道具、进度条修正仍待开发。本文不是完成报告。

## 1. 评审结论

方向成立：奖励只表现已保存的事实，动画不发奖；无尽一次落子仍是一次交易；按实际奖励类型展示；复用现有素材（`icon_coin/energy/hint/exp`、`icon_chest` 两态、`fx_coin_fly/fx_exp_fly/fx_glow_burst`、四张纸屑、`fx_line_clear`，已核对均在交付清单中），不需要新美术。

### 1.1 确认的代码缺陷（必须修）

| 编号 | 位置 | 问题 | 处理 |

### 1.2 对原设计的修订（已写回 09）

| 原设计 | 问题 | 修订 |
| --- | --- | --- |
| 进度条 `Track → FillViewport → FillVisual` 三层 | 节点层级可以更简单 | 填充元素本身作为左锚遮罩视口，内含一张满宽九宫格图（两层）。曾考虑 `Sprite.Type.FILLED`，但它不支持九宫格，110×42 的填充图拉长后圆头变形，已放弃 |
| 旧 v2 存档补字段的迁移流程、纪录基准“未知”状态 | v2 还没发布，没有玩家存档；AGENTS 已规定不兼容旧存档 | 读档缺字段时按默认值补，不做迁移流程 |
| 落成成长快照持久化、强退后补播经验动画；无尽终局快照、强退后恢复结算画面 | 存档结构和恢复逻辑大幅增加，玩家收益很小（数值已经保存，只是少看一次动画） | 成长结果只在内存里给动画用；无尽结算不恢复。奖励弹窗仍按展示队列补展示（R2） |
| 低动态降级模式（不加设置入口） | 没有入口就没人能开，等于死代码 | 首版不做 |
| `AnimationTimings` 全部时长和视觉参数进 Excel | 参数几十个，配表难维护 | 只放主要阶段时长、快进起点、兜底超时、粒子上限（约 10 项），曲线/半径等留在代码 |
| 无尽道具与结算同批交付、救场态是结算前置 | 与 01 §10.2“无救场道具”冲突，会降低周积分难度；工作量最大、最不确定 | 道具放到最后一批，消除和结算先按“无落点即结束”完成；道具待试玩决定，开启时同步改 01 §10.2 和 02 的 S20 |

### 1.3 实施时要注意的点

- 结算弹窗打开时顶栏在遮罩下面。特效层放在弹窗之上，飞行终点仍是顶栏图标，到达时图标轻弹、数值滚动（09 §4.1 已补）。
- S20 托盘框底边在设计 y=1634，到说明行只有 62 单位。加道具按钮时要占用说明行位置，说明文字移到托盘上方或“?”帮助里。
- “换一手”用 `icon_replay`，这个图标在拼图页表示“重玩”，必须配文字。
- 顶栏数值滚动期间，体力恢复或其他交易也可能改值，滚动结束时一律同步到真实值。

## 2. 开发计划

单人按批次推进，每批：代码＋重新生成的 Prefab＋配置（如有）＋测试一起提交；做完跑 `npm test`、`npm run typecheck`，打包装到真机，用总览截图核对。每批结束等用户确认效果再提交推送 dev。
