## 3. 共享数据与表现契约

### 3.1 保存与确认

- 沿用唯一 `Game.act → Store.commit` 权威，保存成功后才发布新状态；奖励入账仍由原交易完成。
- 奖励凭据保存事件 ID、实际奖励和展示必要快照。读取/会话内占用不删除；展示稳定或明确快进后按 ID 确认。普通奖励、合并等级奖励、成长表现、终局结果分别确认自身身份，不互相替代。
- 终局提交把结果原因、gameId/attemptId、分数或结果、纪录基准、结束时 best、周身份/贡献/累计与待展示标记保存，再在同次交易清理运行局。拼图失败也需要可恢复结果；保局不生成终局结果。
- 无尽周贡献取真实逐步累计；跨周按当前周实际增量，不把总分再记一次。恢复展示使用原快照，不能重发奖或重计分。
- 成长快照包含 buildId、实际经验增量、前后等级/经验、逐级分段与关联奖励 ID；旧版本已结束且没有快照的历史交易不追溯伪造。
- 旧 v2 局补字段必须通过正式保存边界；失败可重试且原局不丢失。纪录基准未知为显式状态，不填猜测数字。不因新增字段校验将有效旧局静默重置。

### 3.2 调度与所有权

- 导航、主结算、公共领奖用同一流程身份约束；阶段至少区分提交中、玩法收尾、明细、稳定可交互、取消。过期回调检查流程 ID 与页面状态。
- 播放器不依赖建造 Controller，不持有钱包写接口；输入锁与按钮防重入由页面/流程统一释放，失败、超时、后台、销毁都可收拢。
- 明细未显示成功不能确认；切后台已提交交易不回滚，回前台稳定展示。展示值只控制 Label，不覆盖后来事务或体力恢复后的权威值。
- 图标目标为当前 View 的具体绑定，转换到同一特效层；目标不存在则留明细。实例先销毁，再释放所属 scope，取消需幂等。

### 3.3 配表

沿用 `config/excel/` → `game-config.json`。B0 先明确 `AnimationTimings` 与 `EndlessTools` 字段并由集成人维护配置类型、解析、导表校验和默认规则；不建立第二套配置系统。

最小字段覆盖完整/低动态时长、快进起点、兜底超时、粒子预算、换牌/锤子新局次数、开放条件、候选重试上限。09 的建议数值作为可调首版默认值，不升级为已平衡的用户确认值；计数和上限校验整数范围，时长校验有效范围。经济奖励继续复用原奖励表，播放器不复制奖励配置。
