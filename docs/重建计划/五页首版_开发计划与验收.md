## 4. 并行对话与文件所有权

实际采用本对话统一集成，原生子代理分别承担配置、状态、拼图、美术和引导；共享入口由集成人串行修改。

| --- | --- | --- |
| config_implementation | config/excel、tools/meta、features/config/MetaManager.ts、合并配置 | 不改Boot/导航/其他页面 |
| state_implementation | features/progression/GameStateStore.ts、GameServices.ts、progression.test.mjs | 不造第二存档权威，不改视图/资源 |
| puzzle_implementation | features/puzzle、PuzzlePage.prefab、puzzle.test.mjs | 不改钱包/建造/其他页面 |

| guide_implementation | features/guide、GuideOverlay.prefab、guide.test.mjs | 不直接发奖、改等级或操作第二份存档 |
| root集成 | FirstReleaseBoot、Main.scene、全局资源注册/生成器所有权、最终验证及本文状态 | 不覆盖其他工作线正在写入的文件 |


实际任务领取前登记：负责人、精确文件/目录、允许写入范围、前置接口、输出和验收项；重叠文件归一个人。共享Prefab由一人保存，不能两个Creator实例同时写同一资源。美术线要改拼图Prefab时交给拼图线集成，不能双方并发覆盖。

若各对话在同一目录：只接受严格不重叠写入，禁止并发运行全局生成器、全量删除、重排UUID或切换同一工作树分支。最终Creator导入和注册表更新串行执行。

若使用Git worktree：工作目录隔离能减少直接覆盖，但集成仍可能冲突；本项目Git根在 `Project/`，`arts/效果预览/效果图v2/` 等存在未提交/未跟踪成果，生成器还依赖同级唯一 `prototype/`，新worktree不会自动具备这些输入。先固定可恢复基线、核对美术与原型依赖、工具相对路径和Creator UUID，再交给分支任务。不要为worktree复制第二套正式原型或换4291端口；不要同时往同一链接目标写美术文件。

当前已实施，使用同工作区原生子代理；未创建额外用户对话、worktree或自动化。后续对话仍须先读三份文档、领取单一工作线，不重复重做整个游戏。
