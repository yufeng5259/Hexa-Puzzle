# Honey Garden（Hexa-Puzzle）重建计划 · 总入口

更新：2026-11-03

## 这套文档是做什么的

按 BigHero2415 的框架方式，在 Cocos Creator 3.8.8 中重新搭建 Hexa-Puzzle（游戏名 Honey Garden）。

- 单机，没有服务器。
- 首发平台是 Android 和微信小游戏，其他平台以后再扩展。
- 页面、弹窗、列表项都做成 Prefab 拼装。
- 开发顺序：**先把整体流程串起来（灰盒可玩），再做细节动效和打磨。**

已有的玩法规则（`docs/策划/功能/F001–F065`）仍然是**规则来源**。现有的代码、Prefab 和生成流水线不再延续，只保留题库数据和几个纯逻辑文件（见 [07_复用清单](07_复用清单.md)）。

2026-11-05 起按 [开发方案](../开发方案/README.md) 与 [开发约束](../开发方案/开发约束.md) 执行；两者与本计划冲突时以开发方案为准。

## 一句话结论

1. **玩法规则齐全**：65 项功能都有策划，数值清楚，题库 110 题可直接使用。
2. **BigHero 是 Creator 2.4.15 工程**：约 40 个纯逻辑文件可以原样复制；UI 管理、资源、音频、列表要按 3.x API 改写；它“遍历整棵节点树注入依赖”的做法不照搬。
3. **现有工程大部分丢弃**：82 个 Prefab 是从已经不存在的原型脚本生成的，不能维护；保留题库、六角坐标、拼图规则模型、布局数学这几块。
4. **美术基本齐全，但必须处理后才能用**：原图共 121MB，超过微信小游戏总包 30MB 的上限，需要降采样、压缩、打图集、分包。另外缺音频、字体、图标、第二园地形等，见 [05_美术需求](05_美术需求.md)。

## 里程碑一览（详见 04）

| 阶段 | 目标 | 退出标准 |
|---|---|---|
| M0 工程基线 | 清理工程，移植框架，搭好美术处理流水线 | 空壳能在浏览器、微信开发者工具、Android 上从 Loading 进入地图 |
| M1 主线闭环 | 地图 → 预览 → 拼图（普通/限步）→ 结算 → 下一关，存档 | 能从第 1 关通到第 96 关，杀进程后进度不丢 |
| M2 家园闭环 | 三园建设、完工奖励、下一主题、首轮引导 | 用花蜜建完三园并进入“内容完成” |
| M3 无尽 | 37 格无尽、消除、计分、收获 | 一局完整无尽可结算并入账 |
| M4 外围系统 | 任务、签到、蜂友、相册、衣柜、成就、活动、信箱、设置、帮助 | 所有入口都能打开并按规则发奖 |
| M5 广告与平台 | 5 个广告位，Android 和微信 SDK，分包构建 | 两端真机能看广告并正确发奖 |
| M6 表现打磨 | 动效、粒子、音效、过渡、适配、性能 | 中低端机稳定 60/30fps，四种尺寸无遮挡 |
| M7 验收发布 | 全量回归、包体、真机、提审材料 | 两端可提交审核 |

M1–M4 是“流程串通”，只做必要的反馈（如吸附、数字变化），不做精细动效；M6 统一做表现。
