## 3. Excel共同格式与类型

每个Excel只有第一个sheet参与导出；可保留说明sheet，但不能在其他sheet藏运行数据。保留原工具三行表头习惯：第1行中文说明、第2行类型、第3行字段名，第4行起数据。首个有效字段为 `id`。表名严格采用文件名，大小写一致。

| 类型 | 规则 |
| --- | --- |
| `int` | 安全整数；币、费用、等级、序号均不接受小数 |
| `number` | 有限数；适用于坐标、缩放与透明度 |
| `string` | 保留字面文本；ID不能被 `parseInt` 截断 |
| `bool` | 接受 true/false 与0/1；其他值报错，不自动当false |
| `json` | 必须严格解析；数组/对象再按字段结构校验，不把坏JSON退回普通字符串 |
| `null` 或空类型列 | 注释列，不导出、不影响有效字段数组对齐 |

空白整行忽略；部分字段为空按该字段必填/可空规则处理。列读取按声明字段宽度补齐，不能因末尾空单元格造成行数组错位。必填数值0是有效值，不按空值处理。公式只允许使用可解析的已计算结果，缺少结果时提示另存Excel或填入值，不静默导出公式文本。

ID使用非空字符串；数值ID统一转成无歧义字符串，`1` 与 `"1"` 视同一ID。禁止 `keys`、`__proto__` 等保留键。跨表引用使用同样标准化规则。

## 4. 七个独立Excel的字段

### 4.1 Constants.xlsx

字段：`id:string`、`valueType:string`、`value:string`。`value`先按原始文本读取，再由 `valueType=int|number|bool|string|json` 转换；合并JSON中的value保存转换后的实际类型。这样不同常量可拥有不同值类型，不依靠Excel单列类型猜测。

| id | valueType | 首版值 | 说明 |
| --- | --- | --- | --- |
| energyRecoverSeconds | int | **300** | 用户明确要求：每点5分钟 |
| energyMax | int | 5 | 首版默认，可调 |
| energyInitial | int | 5 | 首版默认，必须在0..上限内 |
| energyFailureCost | int | 1 | 失败、确认放弃或重开扣除 |
| initialCoins | int | 0 | 首版默认，不照抄效果图2350 |
| initialHints | int | 5 | 首版默认，无广告/购买入口 |
| firstMapId | string | garden-1 | 必须存在于Maps |
| firstGuideGroupId | string | first-session | 首轮引导组 |

300秒为已确认要求；初始币0、首奖100、首升级40等是可调首版默认，不是Tile Busters原作数值。恢复扣除策略是本轮规则，不通过可执行脚本文本配表。

### 4.2 Maps.xlsx

字段：`id:string`、`nameKey:string`、`backgroundAssetId:string`、`nextMapId:string?`、`completionRewardId:string`。

首版一行 `garden-1`；无下一地图填空值，不能指向占位地图。背景引用正式裸地图资源ID，不能引用带升级按钮或已烘焙全部建筑的整页效果图。

### 4.3 MapBuildings.xlsx

字段：`id:string`、`mapId:string`、`slotId:int`、`buildingId:string`、`x:number`、`y:number`、`scale:number`、`zOrder:int`、`anchorX:number`、`anchorY:number`、`upgradeOffsetX:number`、`upgradeOffsetY:number`。

每张地图恰好五槽，slotId=1..5且唯一；第一槽是首轮引导升级目标。坐标采用853×1844设计空间、原点为地图根节点中心、x向右/y向上，运行时随地图根的适配变换，不按屏幕像素存表。锚点0..1、scale>0；升级偏移相对建筑锚点，单位为同一设计空间。跨页共享地图实例，切换操作层不重新布置。

### 4.4 BuildingStages.xlsx

字段：`id:string`、`buildingId:string`、`stage:int`、`cost:int`、`bodyAssetId:string`、`effectId:string?`。

`stage=0` 是未建造状态，cost=0且有可显示的状态资源；stage=1..5的cost表示从前一级升入本级的费用。每类建筑等级必须从0连续到最大值；最大等级由行数据推导，不在业务代码写死5或总进度25。首版五级符合五点设计，扩展等级需同时更新表现规格。

五类建筑升入1～5级的首版默认费用统一为40、60、80、100、120，分别写成等级行；这只是可调试跑价格，不是效果图或原作确定经济。第一槽0→1费用即40，其余行不能留空或运行时估算；参考旧可用价格时统一币种。可选effectId只映射已注册的Tween/效果，不能执行任意代码。缺等级素材应在接入前处理，不能用高等级建筑伪称未建造状态。

### 4.5 Mainline.xlsx

字段：`id:string`、`levelNo:int`、`puzzleId:string`、`rewardId:string`。

levelNo从1连续递增且唯一，puzzleId必须来自既有110题；首版沿用现有96关编排，把剩余14挑战题依原题索引追加。首关使用适合教学的现有首题；第1关rewardId指向首关奖励，默认100蜜蜂币。普通/挑战及步数从题库读取，不把效果图18步写入所有关。

首版每题使用一次，导出器检查题目映射完整性；实际数量由合法行决定，不能在通用加载器里强制永远110。新增几何题继续走关卡数据流程，不在Excel填大段拼图JSON。末关完成后Play显示完成态，不制造不存在的下一题。

普通题显示已用步数，不因计步而新增失败上限；挑战题显示剩余步数，读原题moveLimit。本轮已只读核对1.0.0提交中的 `assets/scripts/gameplay/GameplaySession.ts` 与 `SessionStats.ts`：有效位置改变和取回托盘各计1步，取消/非法弹回/放回相同位置不计步；提示激活只记录提示使用，不增加moves。当前PuzzleSession需适配相同位置无操作，不能保留重复落同位置也计步的差异。

本次撤销按钮定义为“取回最近放置拼块”：取回计1步，不回退历史计步；无已放置块时无操作，挑战关已失败后不允许撤销绕过失败。手动取回亦同。提示给出目标格轮廓和冲突块标记，不自动移动或补齐棋盘；首次有效激活时在同一事务中扣1提示并保存activeHintPieceId，扣减保存失败不激活。重复点击当前激活提示或重启恢复不再次扣，目标正确放置/本局结束才解除；玩家正常放置仍按规则计步。触摸落点不合法不消费提示或体力。操作细节应在D07用针对性回归锁定。

### 4.6 Rewards.xlsx

字段：`id:string`、`coins:int`、`energy:int`、`hints:int`。数值均非负安全整数；没有的奖励填0。

默认建立 `first-win`（100币）、`normal-win`（100币）和 `map-complete`（100币、1提示）的可调样例配置；首版只发对应关卡首通奖与每张地图一次完工奖，无重复刷关收益入口。能量奖励不超过上限，溢出部分不储存。奖励表定义“给多少”，收据定义“是否发过”，两者分开。

### 4.7 GuideSteps.xlsx

字段：`id:string`、`groupId:string`、`nextStepId:string?`、`triggerEvent:string`、`pageId:string`、`targetId:string?`、`action:string`、`completeEvent:string`、`params:json`、`textKey:string?`、`shape:string`、`offsetX:number`、`offsetY:number`、`padding:number`、`width:number?`、`height:number?`、`radius:number?`、`handOffsetX:number`、`handOffsetY:number`、`skippable:bool`、`timeoutSeconds:int`。

action首版仅 `click|drag|wait|continue`；shape为 `none|rect|roundRect|circle`。params有固定结构，可配置pieceId、targetCell（目标棋格q/r）、mapId、slotId、expectedStage、dragSourceTargetId、dragDestinationTargetId、pageId和mode。expectedStage表示提交后的目标等级（首次为1），区别于升级命令校验升级前等级的expectedStage（首次为0）。回家步骤匹配pageId=home且mode=home；进入建造步骤匹配pageId=home且mode=build，不能被任意page.ready推进。所有可填键、枚举与字段组合需校验；未知动作直接报错。目标ID写注册名，不写Node路径或脚本表达式。

首轮组不可跳过；首次点击建造与升级都是独立步骤，不以“拼图已完成”提前结束。表中必须存在首轮组唯一入口、合法下一步和终点，首版不允许步骤环。强制步骤超时不释放输入；目标缺失保留阻挡并等待重新绑定，错误可受控重试，不伪造完成。

动画追加使用可选 `params.presentation` 对象，缺省或空对象兼容旧表，未填写项由引导Prefab/表现组件默认值补足。字段均为有限number，字符串数字不接受：

| 字段 | ftue-drag本次配置 | 约束与含义 |
| --- | --- | --- |
| handWidth / handHeight | 140 / 200 | 正尺寸，单位为引导层设计空间 |
| handTipX / handTipY | 表中不固化，Prefab读取record.tipAnchor=0.2375 / 0.948125 | 0..1归一化手套指尖触点，以实际美术记录为准 |
| sourceHold / pressDuration / dragDuration | 0.25 / 0.15 / 0.9秒 | 均>0，源停留、按下及拖动时长 |
| destinationHold / fadeDuration / loopDelay | 0.2 / 0.2 / 0.25秒 | 均>0，目的停留、淡出及重播间隔 |
| pulseDuration | 1.1秒 | >0，高亮呼吸周期 |
| pulseMinOpacity / pulseMaxOpacity | 70 / 190 | 0..255且min≤max；省略单侧时与对应默认70/190比较 |
| instructionX / instructionY | 140 / -195 | 提示文案在引导层的坐标，允许负值与0；横向避开拖起的大拼块和手套路线 |

不添加动画字段列或额外工作簿，仍为七独立Excel合并单JSON。`ftue-drag`的pieceId、targetCell和两个拖动目标ID保持真实题引用，仅新增presentation；timeoutSeconds=0表示不按等待时长自动结束教学循环，至真实放置提交或页面退出停止。首轮其他强制步骤同样timeoutSeconds=0；超时不能绕过强制权限。非法对象、未知表现键、非有限数值、非法范围均报GuideSteps行/字段错误且不覆盖旧JSON。

手套根节点定位指尖：ftue-drag的handOffsetX=0、handOffsetY=0，取消旧emoji的-35纵偏移，使指尖对齐源/目的真实格心。触点比例仅由Prefab读取美术record.tipAnchor，不重复写入Excel。

## 5. 合并JSON与导出保证

保留 `keys + ID对应数组` 编码，加schemaVersion和tables外层。键排序及字段顺序稳定；不写每次变化的构建时间戳，避免无意义diff。示意：

```json
{
  "schemaVersion": 1,
  "tables": {
    "Constants": {
      "keys": ["id", "valueType", "value"],
      "energyRecoverSeconds": ["energyRecoverSeconds", "int", 300]
    },
    "Maps": {
      "keys": ["id", "nameKey", "backgroundAssetId", "nextMapId", "completionRewardId"],
      "garden-1": ["garden-1", "map.garden1", "garden1.background", null, "map-complete"]
    }
  }
}
```

上例省略其他五表，仅解释编码，不是可交付配置。正式文件必须包含七表；数组长度与keys一致，行内id与外层ID一致。字符串ID不经parseInt；MetaManager解码为只读对象和索引，不将数组位置泄漏给业务。

导出顺序：扫描白名单七表→排除 `~$` 临时文件→解析与类型校验→建索引→跨表/首引导校验→序列化→写同目录临时文件并回读→替换正式JSON。失败非零退出，打印文件/sheet/行/字段及原因，不写部分成果；Windows替换失败保留原文件并报错。BAT使用带引号的自身目录及可靠退出码。

最低校验：文件齐全、头字段唯一、类型有效、ID唯一、数值范围、坐标合法、五槽、建筑等级连续、外键、资源ID可达、主线连续、题目唯一、引导next/target声明有效；启动引导建筑存在且初始币+首奖≥首次升级费。没有可证明的资源ID映射时不能以存在同名PNG代替通过。

## 6. 初始化与管理器接口

初始化：创建现有资源scope→加载源资源登记/必要Prefab与题库→加载合并配置→MetaManager校验索引→GameStateStore读档/版本处理→结算离线恢复→建立服务→按引导状态路由。Loading配置失败提供重试和明确错误，不带着缺表进入主页。

| 服务 | 最小入口 | 边界 |
| --- | --- | --- |
| MetaManager | `getConstant<T>(id)`、`getMap(id)`、`getMapBuildings(mapId)`、`getBuildingStage(buildingId,stage)`、`getMainline(levelNo)`、`getReward(id)`、`getGuideStep(id)` | 提供只读配置，不发奖励、不扣费 |
| GameStateStore | `read()`、`transact(commandId, update)`、`subscribe()` | 唯一持久状态权威；串行提交、校验、落盘成功再发布 |
| GameServices：关卡与奖励 | `startOrResume()`、`saveAttempt(snapshot)`、`completeAttempt(attemptId)`、`endAttempt(attemptId,reason)` | 实际统一业务门面；关号、首通收据、局状态和失败费用同事务更新 |
| GameServices：体力 | `refresh()`、`secondsToEnergy()` | 时钟由构造端口注入；入场检查在startOrResume，不另建EnergyService |
| GameServices：建造与设置 | `upgrade(mapId,slotId,expectedStage)`、`mapProgress(mapId?)`、`claimMap(mapId?)`、`updateSettings(patch)` | 保存后发事件；不另建第二套BuildingService或钱包权威 |
| GameServices：引导里程碑 | `getGuidePhase()`、`reconcileGuide()`、`setGuideStep(stepId)` | 首通、指定首次升级、欢迎领奖三阶段判断；旧completed=true优先兼容；保存引导步骤 |
| GuideManager | `start(stepId,context,trigger)`、`resume(context)`、`onEvent(event)`、`pageReady(pageId,mode?)`、`suspend()`、`retry()`、`dispose()` | 配置状态机；不直接增币、改等级或操纵存档副本 |
| GuideTargetRegistry | `register(id,target)`→解除注册函数、`resolve(id)` | 具体Node/几何通过页面绑定和实例注册，不扫描名称 |

## 8. 体力的精确定义

体力单位是点，时间戳统一毫秒；恢复间隔统一取 `intervalMs=Constants.energyRecoverSeconds*1000`，首版300秒即300000毫秒，代码不得写死300000。新档读取energyInitial（首版5）；等于energyMax时nextEnergyAt为空，低于上限则从初始化时刻加intervalMs开始恢复。上限至少1、恢复间隔为正、初始值须在0..上限。刷新时先使用 `effectiveNow=max(now,lastSeenAt)` 防止时钟回拨导致负倒计时，并在同次提交更新lastSeenAt；本地时间方案不承诺防作弊。

若未满且nextEnergyAt已到，恢复 `floor((effectiveNow-nextEnergyAt)/intervalMs)+1` 点，最多到energyMax；未满则nextEnergyAt顺延对应间隔，满值则清空，不能储存满体力期间的额外恢复。

普通新局开始检查energy>0，但不扣；成功不扣。首次教学首局的创建和重建豁免体力入场检查，零体力也可进入，其资格依据首轮未完成且首关未结算的业务状态确认，不能由任意调用者随意传标记。失败、确认放弃、确认重开扣energyFailureCost一次，energy最低0。取消放弃/重开确认不扣费、不改局。未满已有计时则保留原恢复进度；由满值发生首次扣除时设置nextEnergyAt=effectiveNow+intervalMs。奖励增体力后满值也清空计时。

重开先幂等结束旧attempt，再检查扣费后能否创建新attempt；无体力则打开不足弹窗，不能复活旧失败局逃避扣除。创建新局生成新attemptId，与旧局费用收据分离。

普通关没有限步失败时，体力支出来自玩家确认放弃/重开；不得擅加统一步数。教学首关失败/放弃/重开豁免扣除，也豁免创建/重建教学首局的入场体力检查。除该教学例外，零体力允许恢复已存在的未完成局，但不能新开；结束后再检查是否允许下一局。设置/暂停/正常关闭仅存局，不执行失败命令。

## 10. 遮罩、拖动与生命周期

页面以具体类型@property绑定按钮/Label/Node，再注册稳定目标ID；动态棋格/建筑实例由实例组件注册。目标卸载立即解除注册。返回模式后的slot目标重新注册，不能复用失效Node引用。Registry只负责定位，不负责自动创建缺失节点。

遮罩形状与位置相对目标实际UITransform计算，在guideLayer空间绘制；兼容圆、矩形、圆角矩形及源/目标双区域。显式width/height为覆盖值，空值使用目标包围框；padding≥0，旋转/缩放/安全区变化后重新计算。

拖动步骤在源区域按下后，持续捕获同一pointer到抬起/取消；途中允许经过遮罩暗区，不能每帧以洞内命中截断手势。其他触点与无关按钮保持阻止，放置合法性仍由PuzzleController判定。遮罩视觉挖孔与触摸过滤分别实现并验证。

目标尚未出现等待page.ready；强制目标消失时暂停手型并取消当前捕获，但保持动作/输入阻挡并等待重新注册；加载失败提供受控重试，不因超时解除权限。强制教学期间设置入口被禁止。正常游戏打开设置可暂停输入，关闭后恢复；隐藏解除监听，销毁取消自己持有的异步请求与Tween。

循环拖动表现依据当前源/目的目标坐标重算路径，依次停留、按下、移动、目的停留、淡出及等待重播；点击步骤默认轻点。手指触点对齐实际目标，不以图片中心代替触点。目的区呼吸透明度受presentation控制，拖拽目标由棋盘原生落点预览绘制，位于拼图块下层，不再由GuideOverlay重复填充。timeoutSeconds=0只关闭步骤等待计时，不关闭缺目标、页面退出、隐藏/销毁清理；表现取消后不得留下Tween或迟到回调。新表现须单独做真实Creator循环、真实拖放推进及退出清理验证，不能沿用前轮静态手指验收证据。
