# 02 技术架构

> 历史方案：本次使用 [五页首版配置与技术契约](五页首版_配置与技术契约.md)，保留现有框架与唯一存档/奖励权威。下方重移框架、旧目录和外围系统方案不作为本轮实施指令。

依据：BigHero 框架（移植到 3.8.8）、仓库 `AGENTS.md` 的 Prefab 约束、微信小游戏和 Android 的限制。

## 3. 启动流程

```
Boot.scene 加载
 → App.onLoad：
    1. 初始化平台（Web / 微信 / Android），注册前后台切换和音频中断
    2. 读存档（SaveService.load，同步完成），坏档时备份并进入恢复流程（F065）
    3. 打开 LoadingView（resources/boot 中的小图，立即可见）
    4. 依次执行带进度的步骤：
       加载 common 包 → 加载配置表 → 加载语言 → 初始化音频 → 预加载 puzzle 包 → 业务时钟跨日检查
    5. 进入主界面：MapPage；如果有未完成的局，弹出“续玩”（F013）
```

## 4. UI 框架

### 4.1 分层（Boot.scene 中预置的节点，全屏 Widget）

| 层 | 用途 | 规则 |
|---|---|---|
| `Layer_Page` | 全屏页面：地图、家园、拼图、无尽、各回流页 | 同时只显示栈顶页面；打开新页面时下层页面隐藏（`active=false`），不销毁，除非标记了 `destroyOnHide` |
| `Layer_Popup` | 弹窗 | 可以叠放；支持排队（奖励弹窗依次出现） |
| `Layer_Guide` | 新手引导遮罩 | 在弹窗之上 |
| `Layer_Toast` | 飘字提示 | 不拦截输入 |
| `Layer_Block` | 加载遮罩，以及过渡期间的输入屏蔽 | 最上层 |

### 4.2 打开页面：按类型，不写字符串路径

```ts
@ccclass('PuzzlePage')
@uiView({ bundle: 'puzzle', path: 'prefabs/pages/PuzzlePage', layer: UILayer.Page })
export class PuzzlePage extends ViewBase<PuzzlePageArgs> { ... }

await ui.open(PuzzlePage, { levelNumber: 12 });
ui.close(this);
```

- `ViewBase` 的生命周期沿用 BigHero 的钩子：`onOpen(args)`、`onShow`、`onHide`、`onClose`、`onBack`。
- **防止迟到的结果**：页面关闭后，它发起的异步加载即使完成也直接丢弃，不写入已销毁的节点。
- **资源归属**：View 通过自己的 `ResourceLease` 加载资源，关闭时统一 `decRef`。
- **Android 返回键**（`KeyCode.MOBILE_BACK`）：先关闭最上面的弹窗；没有弹窗时调用当前页面的 `onBack()`；在主地图上弹出“退出游戏”确认框。拖动过程中按返回键，先取消拖动（不提交）。

### 4.3 Prefab 制作规范（来自 BigHero 两个范例，必须遵守）

1. **页面根节点**：全屏，挂 Widget 和对应的 View 组件，节点名与类名一致。
2. **弹窗统一结构**：`Root{XxxPopup} / Backdrop(半透明遮罩 + BlockInputEvents) / Content(面板)`。Backdrop 和 Content 用 `@property` 绑定，供过渡动画使用，不按 children 下标取。
3. **引用都在 Inspector 里绑定**：所有需要访问的 Label、Sprite、Button、子节点、子 Prefab 都用 `@property` 绑定。**禁止** `getChildByName`、`find`、按下标取节点、运行时遍历整棵树。
4. **固定按钮在 Prefab 里绑定点击**：`clickEvents` 指向根 View 的 public 方法，参数放在 `customEventData`。
5. **状态节点预先放好**：选中、禁用、红点、锁定等状态做成预置的子节点，View 只切换 `active`，不在运行时创建。
6. **列表**：`ScrollView + Mask + content` 与 `ScrollableItemGrid` 挂在同一节点；cell 是独立的 Prefab，根节点挂 `ItemGridCell` 子类。
7. **可复用的部件做成嵌套 Prefab**：HUD、通用按钮、奖励项、货币计数器、标题木牌、弹窗面板等，在页面中以嵌套 Prefab 使用。
8. **文字**：Label 统一使用项目字体（见 06 的 E05）；变化频繁的数字使用 BMFont 或 `CacheMode.CHAR`；文字内容走本地化 key，不写死在 Prefab 里。
9. **九宫格**：面板、按钮、底条在导入时设置 border（`arts` 中的 `insets` 都是空的，要逐张设置）。

## 5. 数据与存档

### 5.1 原则（来自 F017 / F019 / F020，必须保留）

- **只有一个存档**：所有玩家状态都在一个 `SaveData` 对象中，用一个 key 存入 `sys.localStorage`。在微信上它会自动走 `wx.setStorageSync`，是同步写入；上限10MB，足够用。
- **命令式修改加原子提交**：
  ```
  const tx = save.begin();          // 在当前快照的深拷贝上修改
  wallet.spend(tx, 'honey', 40);    // domain 层的规则函数只操作 tx
  garden.upgrade(tx, buildingId);
  save.commit(tx);                  // 序列化 → 写入 → 成功后替换快照 → 广播事件
  ```
  写入失败时丢弃 tx，界面保持原状并提示（F017 写失败回滚）。**保存成功之前，不播放到账动画。**
- **幂等领取键**：所有领奖都写入 `claims` 集合，例如 `daily:{day}:play`、`chapter:{c}`、`signin:{d}`、`bonus:{settlementId}`；重复领取直接返回原结果。
- **业务时钟**（F022）：`dayKey` 用设备本地日期，`weekKey` 取当周周一。时间被调回时，保持最后接受的周期，不重置已领取的记录。
- **开发档和正式档分开**：key 分别为 `hexa.save.dev` 和 `hexa.save.prod`，GM 只写开发档（F060）。
- **结构版本**：`schemaVersion` 加迁移函数；未知或更新的版本只读并备份，不覆盖（F018 / F065）。

### 5.2 存档结构

按 [C_策划设计摘要](分析报告/C_策划设计摘要.md) §4 实现，分为 meta、wallet、mainline、attempts、endless、garden、collection、periods、claims、signin、event、mail、settings、guide、ads 这些子域。

**一处简化**：单线程加同步写入已经能保证原子性，所以策划中的事件 outbox 不单独落盘。事件在提交成功后同步分发；跨重启只有广告回执需要恢复，单独保存在 `ads.pending` 中。

### 5.3 配置表（JSON，放在对应包里）

| 配置 | 包 | 内容 |
|---|---|---|
| `levels.json` | puzzle | 题库，由 `level-catalog.json` 压缩而来（坐标改为数组，去掉可推导的 targetCells，预计约100KB），附加 `perfectMoveTarget` |
| `mainline.json` | puzzle | 96关映射、颜色映射 |
| `garden.json` | common | 3园×5栋×5级的升级价格、建筑名称、资源 id、落位坐标 |

## 6. 拼图实现要点

- **坐标**：axial（q, r），复用 `HexCoordinates`。棋盘到像素的换算复用 `PuzzleLayout`。
- **规则模型**：`PuzzleModel` 判断放置合法性和胜负，`PuzzleSession` 负责计步、撤回和限步胜负，两者都是纯 TS，可以单元测试。
- **棋盘渲染**（性能关键）：
  - 每个格子用 Sprite，凹槽、木框、提示轮廓、障碍格都来自 `puzzle` 图集，同一图集可以合批。
  - 棋盘外框和投影这类不规则形状，开局时用 Graphics 画一次，或参照 `运行组件/block_hex_runtime.js` 移植成网格，之后不再重绘。**不要每局反复创建 Mask 和 Graphics。**
  - 拼块 = 若干单格 Sprite 组成的节点，节点用对象池复用。
- **拖放**：
  - 单点触控，第二根手指忽略；
  - 拖动时拼块上移一点，避免被手指挡住；
  - 吸附到最近的合法位置，不合法就弹回；
  - 弹出弹窗、切到后台、窗口尺寸变化时取消拖动，不提交。
  - 逻辑参考 `PuzzleController` 重写。
- **命中检测**：按六角形精确判断，参考 `PuzzlePiecePresentation.containsLocal`。

## 7. 资源与包体

### 7.1 美术处理流水线（`tools/art-pipeline`，M0 完成）

```
arts/游戏素材/PNG（原图，不改动）
  → 读取页面配置，得到每张图在设计稿中的最大显示尺寸 × 0.8793（换算到750宽）× 1.5（高分屏余量）
  → sharp 降采样（不放大）
  → UI 图：PNG 调色板量化；全屏背景：JPG，质量80左右
  → 输出到 assets/bundles/<包>/textures/<模块>/，使用英文 snake_case 文件名
  → 生成 tools/art-pipeline/asset-map.json（原中文名、sha → 新路径，便于追溯）
```

- 原图始终保留在 `arts/`。Codex 补的新图放进 `arts/` 后，重新跑流水线即可。
- **图集**：每个包按模块建 Auto Atlas（不超过2048×2048），例如 `common_ui`、`puzzle_cells`、`home_ui`、`meta_icons`。背景、地形、大插画不进图集。
- **包体目标**：
  - 主包不超过4MB：引擎、全部脚本、Boot 场景、`resources/boot`；
  - 总包不超过20MB，给后续内容留余量。
- **Android 纹理**：可选 ETC2 压缩以降低内存，先用 PNG，M6 再评估。

### 7.2 分包加载时机

| 包 | 加载时机 |
|---|---|
| common、puzzle | Loading 阶段 |
| garden{n} | 第一次进入家园时加载当前园；从地图点击家园按钮时预加载 |

## 8. 性能规则（写进代码评审清单）

1. **合批**：同一界面的 UI 尽量使用同一图集。Label 夹在 Sprite 之间会打断合批，数字用 BMFont 或 CHAR 缓存。避免使用 Mask 和 Graphics，必须用时放在层级末尾。
2. **主地图**：12页×8关，只实例化当前页和相邻页的关卡节点（虚拟分页）。
3. **列表**：一律使用 `ScrollableItemGrid` 复用节点。
4. **对象池**：拼块、六角格、飘字、粒子、飞行的花蜜全部用池子。
5. **每帧不分配内存**：拖动的 `TOUCH_MOVE` 中复用 Vec3，不新建对象。
6. **定时器**：统一使用框架的 Timeline，页面关闭时取消，不残留回调。
7. **内存**：离开家园时释放当前园的地形和建筑纹理；同一时间只保留一个园的资源。
8. **目标**：
   - 中端 Android 和微信稳定60fps，低端机不低于30fps；
   - draw call：拼图页不超过30，地图不超过40；
   - 连续玩10局后内存不持续增长（F064）。

## 9. 平台层

```ts
interface IPlatform {
  showRewardedAd(placement: AdPlacement): Promise<AdResult>;   // 'rewarded' | 'skipped' | 'unavailable' | 'error'
  vibrate(kind: 'light' | 'medium'): void;
  onPause(cb): void; onResume(cb): void;                       // 前后台切换：暂停音频，取消拖动
  share?(): void;                                              // 仅微信
  exitApp?(): void;                                            // 仅 Android
}
```

- **WebPlatform**：用于浏览器预览和开发，内置模拟广告（可配置为成功、失败或无广告）。
- **WeChatPlatform**：
  - 激励视频使用 `wx.createRewardedVideoAd`，参考 BigHero 中 onClose 和 isEnded 的处理；
  - 注册 `onAudioInterruptionBegin/End`；
  - 使用 `getUpdateManager` 检查更新；
  - 调用 `showShareMenu`。
- **AndroidPlatform**：通过 `native.reflection.callStaticMethod` 调用 Java，Java 再用 `evalString` 回调 JS。广告 SDK 待定（06 的 E06）。
- **广告事务**（F052）：请求前先把 pending 记录写入存档，再调用 SDK；奖励写入存档成功后才确认。迟到的回执只作用于原来那一局。

## 10. 测试与校验

- **单元测试**（`tools/tests`，用 `node --test`）：domain 层的全部规则，包括拼图合法性、限步计步、星级、钱包、幂等领取、跨日跨周、无尽消除计分、存档迁移。
- **类型检查**：`tsc --noEmit`。
- **构建**：使用 Creator 命令行构建 web-mobile、wechatgame、android，校验包体大小。
- **人工验收**：每个里程碑结束时，在浏览器、微信开发者工具和 Android 真机上按 [04_开发计划](04_开发计划.md) 的验收项走一遍。
