## 1. 游戏总览

### 1.1 一句话定位
单机、离线可玩的休闲六边形拼图游戏，竖屏，目标平台为 Android 和微信小游戏。玩家在主线中把异形六角拼块平移拼进目标轮廓，赚取**花蜜**，再用花蜜直接升级家园里的建筑。共 3 个主题园，每园 5 栋建筑，每栋 0–5 级。外围系统有：37 格无尽消除模式、三位"蜂友"伙伴与亲密度、相册照片收集、外观衣柜、日/周任务、七日签到、成就、包内野餐活动、本地信箱，以及 5 个自愿激励视频广告位。
没有体力、建造星币、IAP、战斗、真实好友、在线排行、账号云档、第四园，也没有强制插屏或开屏广告。

### 1.2 核心循环
```
Loading → 综合地图（levels，唯一主界面，12页×8关）
   → 选关 → 开局预览(普通/限步) → 拼图局 → 胜利结算(花蜜) → 下一关 / 回家园
   → 家园(home)：点建筑或价签直接花蜜升级(一次+1级，约0.8秒施工)
   → 5栋全5级(25/25) → 领整园完工奖(100花蜜+1提示+合影) → 下一主题预览 → 出发(免费, 新园5栋归0) → 章节剧情 → 新家园
   → 三园全部完成 → "当前内容完成"，进入无消费回流（精选复玩/无尽纪录/相册/蜂友故事）
```
新手第一轮（FTUE，F048）由真实事件推进：初始 120 花蜜 → 首建树屋 Lv1（−40 → 80）→ 回地图打第 1 关（+80 → 160）→ 回家园升树屋 Lv2（−40 → 120），此时建设进度 2/25 → 自由探索。

### 1.3 玩法模式
| 模式 | 规则要点 | 产出 |
| --- | --- | --- |
| 主线普通（classic）80 关 | 异形块只平移、不旋转；整块合法才吸附；目标格全部填满即胜；没有步数或时间失败；3–6 块 | 首通 80；复玩 20/次，与每日精选合计每天 5 次 |
| 主线限步（challenge）16 关 | 位于第 6、12、…、96 关（每 6 关 1 关）；moveLimit 为 7 或 8；落盘、合法移位、已落盘块取回各算 1 步；最后一步填满算胜；用尽算失败，可免费重试；1–3 星 | 首通固定 120；之后星级提高时每星补 20 |
| 无尽（endless） | 37 格（半径 3）六角盘；每轮 3 个候选块（1–5 格），用完 3 块才补发；三轴整线消除；记分和连击；每局可撤回 1 次；可主动收获 | min(120, floor(score/100)×5)，每天上限 240 |
主线共 96 关，按"五普通一限步"编排：第 n 关组号 g=floor((n−1)/6)；组内第 6 位是限步第 g+1 题，其余是普通第 g×5+组内位 题。另有 14 道储备限步题（challenge-017..030）不进主线，只用于旧档兼容和开发审阅。第 96 关之后没有第 97 关。无尽在**真实通关主线第 4 关**后解锁。

### 1.4 外围系统（详见 §2）
- **家园建设**（F023–F028）：3 园 × 5 建筑（0 树屋、1 花园、2 蜂蜜工坊、3 小溪水车、4 温室）× 5 次升级，共 75 次，总价 8800（三园分别 1600/2600/4600）。外观上是 90 种建筑阶段图，另有 15 个旋转转子动效。
- **货币**（F019）：只有花蜜（honey）和提示（hint）两种。新档初始 120 花蜜和 5 提示，只发一次。星级是成绩，不能消费。
- **奖励**（F020）：统一幂等结算，attemptReceipt 记录每次结算，按稳定题 ID 判首通。
- **蜂友 / 亲密 / 剧情**（F035–F037）：小蜜（初始认识）、花花（chapter≥1）、阿工（chapter≥2）。领取每日任务时，当前跟随的蜂友亲密 +1，全局每天最多 3 点，每位蜂友上限 30。亲密 5 解锁招手动作，15 解锁个人故事（3 页），30 解锁专属饰物。
- **装饰 / 衣柜**（F038）：共 5 件外观。0 晴天围巾初始拥有；1 野餐帽来自签到第 7 天；2 花朵帽、3 水湾丝带、4 云朵胸针分别来自三本相册的集齐奖。另有 3 件蜂友专属饰物（亲密 30）。
- **相册**（F039–F040）：3 册共 18 张照片，photoId=chapter×6+slot。slot0–4 是各建筑首次 0→1 升级时的照片，slot5 是整园合影。每册集齐 6 张可领一次：1 提示 + 1 件外观。
- **每日任务**（F041）：3 项。play：3 个有效局 → 120；build：建设 1 阶 → 40（满园后改为"完成精选 1 次"）；endless：12 次有效摆放 → 20（无尽未解锁时改为"再拼一关"）。合计每天 180。
- **每周目标**（F042）：本周有效局 ≥15 且活跃日 ≥4，领 300 花蜜和该周纪念印记。
- **七日签到**（F043）：累计 7 天，不要求连续，不循环。每天花蜜 40/40/60/60/80/80/120（共 480）；第 3、7 天各加 1 提示；第 7 天另给野餐帽。
- **成就**（F044）：3 项，只给徽章。完成 10 个不同主线关；无尽最高分 ≥5000；进入第二园。
- **花园野餐活动**（F045）：包内常驻活动，首园后开放（时机见 D07）。每个有效局 +1，进度上限 20，到 20 领 100 花蜜，一生一次。5/10/15 只是刻度，不发奖。
- **信箱**（F050）：只有 1 封随包欢迎信《欢迎来到小蜜的家园》，没有附件，只记录已读。
- **设置**（F047）：5 项开关：音乐、音效、震动、减少动效、大字。
- **暂停与帮助**（F046）：暂停弹窗；帮助目录下有 3 篇图示：拖放拼图、三轴消除、五级建设。
- **引导**（F048、F049）：首轮 7 步事件式引导（T51-01..07）；限步第 6 关首次的轻提示；无尽首次引导（T51-08）。
- **每日补给**（F057）：每天免费领 1 提示；还有建设目标时，可看视频领 60 花蜜，每天 2 次。
- **激励广告**（F052–F059）：5 个广告位：提示 +1、限步 +3 步、无尽清理续局、结算追加、补给 60 花蜜。全局每天最多 6 次成功，两次成功间隔至少 120 秒，同时受各广告位自身上限约束。前 3 个普通关不主动邀请看广告。所有广告场景都保留免费出路。
- **本地存档界面**（F065），**隐私说明**（F051）。
- **GM**（F060–F061）：只在开发包中提供，需同时满足 DEBUG 和显式配置两道门禁，使用独立的测试档。

### 1.6 解锁时间线
- 新档：只能玩第 1 关；小蜜已认识；只有晴天围巾。
- 真实通关第 4 关：无尽解锁；每日任务的 endless 项从"再拼一关"变为"无尽摆放"。
- 第 6 关：第一个限步关，首次进入时有步数轻提示。
- 首园完工领奖 → 出发第二园（chapter=1）：花花开放；蜂友列表和活动入口开放（原型以 chapter≥1 为准，见 D07）；成就 garden 达成。
- 出发第三园（chapter=2）：阿工开放。
- 第三园 25/25 并领奖：家园全部完成，隐藏花蜜类广告邀请（补给视频和结算追加）。
- 主线第 96 关完成：显示"主线完成"，不再出现下一关。

### 1.7 全局技术规则（影响玩法正确性，重建时必须保留）
1. 只有一个玩家存档权威（F017）。每个命令的流程：读已提交快照 → 校验 → 生成候选（余额、进度、领取键、事件一起放进去）→ 完整原子提交 → 发布快照和事件 → 刷新 UI 和动效。保存成功之前不播"到账"表现。
2. 所有领奖都有幂等键：attemptId、runId、settlementId，以及领取键 `chapter:{c}`、`album:{c}`、`daily:{dayKey}:{play|build|endless}`、`weekly:{weekKey}`、`signin:{d}`、`achievement:{id}`、`event:picnic`、`freehint:{dayKey}`、`bonus:{settlementId}`。重复命令返回原回执。
3. 业务时钟（F022）：dayKey 用本地日期；weekKey 取当周周一。时间回拨时保持最后接受的周期，不重置已领。
4. 输入：单触点。弹层、后台、resize 都会取消正在进行的拖动，且不提交。
5. 广告：先把 pending 请求落盘，再调用 SDK。回执写入成功后才 ACK。迟到的回执只归属原 profile、原 attempt 或 run，不能作用到新局。
6. 四种屏幕尺寸：390×844（基准）、375×667、360×640、320×568。触控区不小于 48px。支持大字和减少动效。

### F001 启动与Loading
- 目标：本地基础资源和题库准备完成后自动进入综合地图（主线地图）。没有登录，也没有离线菜单。
- 规则与数值：
  - 状态机：未开始→准备登记（读取素材manifest与prefab登记表）→装载题库→展示地图。任一步失败都停在可理解的失败态，不能进入半成品地图。
  - 进度只反映真实阶段，不能用定时器假装加载。
  - 接存档后，存档校验与恢复必须在提交首页之前完成：无档时创建默认档；有坏档时走恢复流程（保留备份），不能直接覆盖。
  - 候选资源和候选玩家快照都成功，才提交入口；失败时保留原数据。
  - 启动重入或重试不重复发初始钱包，也不重复发离线奖励。读取失败不能算作"新用户首次初始化成功"。
- 页面/弹窗：`loading`，成功后replace到`mainline-map`。
- 依赖：无（之后接入F017）。
- 数据/事件：运行态字段ready、disposed、请求身份、manifest/目录版本、失败原因。这些不是奖励凭证。
- 验收要点：新安装只出现一个Loading，之后进地图；题库失败时留在失败提示，不显示可点地图；加载中销毁后，晚到的回调不建页面；重复启动不重复写初始余额；有效档恢复、坏档保留备份，存档未保存成功前不宣布就绪。
- 未知/待定：业务恢复与可操作的重试还要接入。

### F002 页面弹窗导航与返回栈
- 目标：只有一个页面层加弹窗覆盖层；支持返回来源、加载取消和输入暂停的归属。
- 规则与数值：
  - 同一时刻只有最上层能发业务动作。
  - 打开弹窗时保留来源页面和题目上下文；关闭后回到来源，而不是固定回家园。
  - 准备新页时立刻暂停底下页面的输入；准备成功才替换。失败或取消时保留旧实例、旧关卡和旧返回栈。
  - 同一目标的重复导航去重；快速点击不同目标时，以最后一个有效请求为准。
  - 导航上下文（presentation、mainlineNumber、levelId、mapPage）只是导航数据，不代表关卡权限（权限由F008判定），也不能凭当前route推断已通关。
  - 请求只提交一次；取消时释放候选资源，不提交候选attempt。
  - 层级：page / dialog / guide 三层。
- 页面/弹窗：无独立页面。
- 依赖：F001。
- 数据/事件：不写存档。按钮发view-action给当前entry。
- 验收要点：拼图→暂停→帮助→逐层返回原局，attempt与步数完全一致；快速选6、12、96只提交96；新页失败保留旧页可重试；覆盖层存在时底页拖放无效；开关设置10次不叠加监听。
- 未知/待定：接档后，切换存档时必须让跨档的导航请求失效。

### F003 资源加载与页面所有权
- 目标：管理资源登记、scope持有、共享加载、请求身份、释放与失败重试。
- 规则与数值：
  - 生命周期：登记→加载→scope持有→实例使用→销毁实例→释放scope。
  - 共享同一资源不等于共享页面所有权。关闭一个页面只减少它自己的持有。
  - 失败不永久缓存，允许重试。资源未登记、类型或UUID不符时直接失败，不能静默换替身图。
  - 晚到的资源不能复活旧节点；释放操作幂等。
- 页面/弹窗：无。
- 依赖：无。
- 数据/事件：资源记录{id, bundle, path, type, uuid}。不写玩家档，不发获奖事件。
- 验收要点：两页共用一个资源，关闭其一后另一页正常；加载中关页不残留引用；bundle首次失败后重试能成功；错误UUID或未登记ID给出明确错误。
- 未知/待定：分包和内存预算按批审核。

### F004 通用UI组件与绑定
- 目标：提供可复用的通用组件：按钮、图标按钮、资源HUD、资源计数器、标题栏、对话框框体、进度条、开关、Toast。
- 规则与数值：
  - 组件只展示输入、输出意图，不持有经济或关卡权威。
  - HUD显示真实快照，不能把原稿上的数字当余额。

### F022 业务时钟与跨日跨周
- 目标：提供可注入的日期权威，统一日/周键和回拨处理。

  - 差额 = **max(0, 下一次价格 − 当前花蜜)**，实时计算，不缓存旧值；余额刚好够时恢复可升级。
  - 不足时提示“还差 N 花蜜”，保留当前园、建筑选择和来源入口，可去主线或返回。只解释缺口和可选回流，不强制看广告。
  - 回到家园时重新取钱包快照，差额归零即清除提示。按钮禁用只是视觉反馈，业务命令仍会校验。
  - 点满级建筑不提交扣款。总和到 25：未领奖→显示完工礼（F026）；已领且不是第三园→显示下一园（F027）；第三园→F028。
  - 直接打开 home-max 或 build-short 状态不改存档，也不触发完工奖励。
- 页面/弹窗：home-max（T15-02_家园_单栋满级）、build-short（T15-04_家园_花蜜不足回流），都是家园页的状态。
- 依赖：F019、F023。
- 数据/事件：读 buildings、honey。shortageBuilding 是瞬时选中 ID，shortage 是派生值，都不落盘。进度只由 BuildingUpgraded 成功或存档恢复更新；WalletChanged 触发差额重算。
- 验收要点：余额 15、向阳树屋 0 级→显示还差 25，连点不扣款；补到 40 后回来，提示消失，升级后余额 0；一栋 5 级其余 0 级→进度 5/25；24→25 后进度不超 25，进入未领奖状态。
- 未知/待定：最终文案和大字排版以原稿为准；原型里预置的 shortage=25 只是夹具。

### F026 整园完工唯一奖励
- 目标：每园五栋全 5 级后主动领取一次完工奖励。
- 规则与数值：
  - 领取资格：当前园 building[0..4] 全为 5，且该园未领过。
  - 每园固定奖励（一生一次）：**100 花蜜 + 1 提示 + 该园整园合影**。三园合计 300 花蜜、3 提示、3 张合影。
  - 合影 ID = **chapter×6+5**，加上 5 张首建照片，每园共 6 张。
  - 非满级的领取请求被拒绝；已领时显示“已领取”或后续入口，不再发奖。出发不收费。
  - 最后一次升级保存成功后提示完工。弹窗可以关掉稍后从家园再开；打开弹窗、庆祝动画或看图都不算领取。
  - 点领取时重新读当前园和五栋等级，锁定 chapter 领取键，把花蜜、提示、合影、回执、chapterFinished 一次提交。失败可重试，不能出现只到花蜜或只有回执的半成品。
  - 领取成功后：非末园进入 chapter-next，末园按 F028 处理。领奖之前不能出发。
- 页面/弹窗：chapter-complete（可关闭重开的领奖弹窗），T16-01_整园完工奖励；用奖励条目展示花蜜和提示。
- 依赖：F017、F019、F023。
- 数据/事件：领取键 `chapter:{chapter}`；chapterFinished 只是派生缓存，不能与 claims 矛盾。事件 **GardenRewardClaimed**{chapter, receiptId, 100, 1, photoId}；重复命令返回原回执。历史园的奖励归各自园。
- 验收要点：24/25 伪造领取→拒绝，库存不变；25/25 首次领取→+100、+1、+1 合影同次保存；双击、重开、冷启重放都只到账一次；三园的领取键独立，合影不串园。
- 未知/待定：**D07**：首园领奖后是否开放蜂友/活动未定。原型要等出发（chapter 增加）才开放。

### F027 下一主题解锁与世界地图

- 规则与数值：
  - 章节索引：0 向阳花园、1 清风水湾、2 云上蜂谷。没有第四园，没有付费解锁，不重置旧园。

  - 流程：家园完成→领奖→chapter-next 预览下一园→点出发时重新校验完工回执→原子更新 chapter 和建筑数组（一次提交）→进入章节故事→回到新家园。
  - 出发命令带 expectedChapter：第一次成功后旧请求失效，连点也只前进一园。新园加载失败时进度已保存，可重试打开。

- 页面/弹窗：chapter-next（T17-01_下一主题_清风水湾、T17-02_下一主题_云上蜂谷）、world-map（T27-01_三园世界地图，含主题卡条目）。
- 依赖：F023、F026（并引用章节故事、相册）。
- 数据/事件：chapter、当前 buildings。成功事件 **GardenEntered**{from, to, commandId}，供蜂友、成就、剧情读取。
- 验收要点：24/25 或满级未领奖→出发被拒；向阳领奖后出发→chapter=1、五栋 0 级、不扣花蜜；同一出发命令执行两次仍停在 chapter1；第三园完成后再请求 next→进入完成提示，没有第四卡。

### F028 全部内容完成与无消费回流
- 目标：区分主线完成和三园完成，给内容已完成的玩家提供可持续的回流入口。
- 规则与数值：
  - 主线完成以 F008 的真实 **96 关**完成记录为准，不用原型旧的“普通 80 关”字段。
  - 家园完成 = chapter 2 且五栋全 5 级；完工奖是否已领单独看 F026 回执。
  - 两种完成互不替代：主线完了园没完，仍有花蜜消费目标；三园完了主线没完，仍可继续主线。
  - 三园满级后隐藏花蜜视频补给和结算追加广告邀请（已没有消费目标），已有花蜜保留，免费游戏入口照常可用。
  - 末园未领奖时仍可领 100 花蜜 + 1 提示 + 合影，不会被完成态挡住。
  - 可返回的去处：地图、每日精选、无尽纪录、相册、蜂友故事，都回到实际来源。之后的重复游玩沿用原奖励规则和额度；打开完成页不重置额度、不发奖；没有第四园，也没有无限消费口。
- 页面/弹窗：journey-complete（T18-01_当前内容完成）、home-finished（家园页状态，T15-05_家园_第三园全部完成）。
- 依赖：F008、F026、F027（广告资格引用 F052）。
- 数据/事件：mainlineCompleted、gardenComplete、hasHoneyGoal、claims 分别命名，不合并成一个 isFinished。广告资格和按钮共用同一个消费目标查询，页面打开和广告回执时都重新判断。诊断事件 ContentMilestoneViewed 不用于发奖。
- 验收要点：96 关完成但第三园 24/25→升级和消费入口照常；三园 25/25 但主线未完→可继续主线，不显示全通；三园满级后结算页和补给处没有花蜜广告；重复打开完成页，各项数据不变。

### F029 无尽入口解锁与保局
- 目标：无尽在主线进度达标后开放，优先恢复活跃局。
- 规则与数值：
  - 真实通关主线**第 4 关**后解锁，不花货币、不看广告。只是选中第 4 关不算。
  - 有未结算的 run 时，主按钮是“继续无尽”，恢复同一个 runId；没有活跃 run 才新建。
  - 开新局会丢弃未收获的进度，必须先确认或先收获；取消则原局完整保留。被丢弃的旧局不算有效完成，不刷任务。
  - 新建时先生成唯一 runId、种子、首轮候选和初始快照并持久化，成功后再导航。重复点击复用同一次创建的回执；导航失败不再建新 run。
  - 返回、暂停、冷启都优先恢复，不默认重新发牌。
  - 前 **2 局固定种子：20261016、20261017**，之后使用可保存的随机状态。
- 页面/弹窗：endless-intro（T11-01_无尽玩法入口，兼作入口和继续状态）；未解锁时说明需通关第 4 关，可返回主线。
- 依赖：F008、F017。
- 数据/事件：activeEndlessRunId；run 字段：id、seed/rngState、board、tray、score、combo、placements、continues、undoUsed、previous、settled。原型 endlessRuns 只在有效结算后 +1。
- 验收要点：只选中第 4 关→仍锁，真实通关后立即解锁；退出再进时 id、棋盘、3 个候选、分数、随机状态完全一致；双击或重试不会产生第二个 run；新局确认框点取消，棋盘和撤回次数不变。
- 未知/待定：“前 2 局”按什么计数（有效结算次数还是创建次数）待确认，不能擅自按点击次数算；原型里无确认的 new-endless 分支不能作为正式授权。

### F030 37格无尽发牌放置与三轴消除
- 目标：独立于主线拼图的六边形放置消除核心。
- 规则与数值：
  - 棋盘用轴向坐标 q、r ∈ [−3, 3] 且 |q+r| ≤ 3，共 **37 格**；第三轴 s = −q−r。
  - 每条轴 **7 条线**，线长随盘边变化（并非每条 7 格）。
  - 每轮 **3 个候选**，每块 **1–5 格**，不能旋转，只能平移。三块全部用完才补发 3 块，用掉两块时不补。
  - 合法放置：所有格都在盘内且不重叠。非法时拼块回托盘，分数、步数、随机状态都不变。
  - 消除：放置后基于完整棋盘一次找出三轴所有满线，清除它们的并集，交叉格只清一次；不能逐轴边删边判。
  - 每步流程：选块或拖块→预览合法目标→松手时再校验→保存放置前快照→写入格子→判满线→清并集并按 F031 计分→消费候选→需要时发新一轮→保存→检查剩余候选还能否放下（转 F033）。
  - 不保证每局一定有解。恢复时不重新抽候选（seed/rngState 确定）。
- 页面/弹窗：endless（无尽对局页：棋盘、托盘、特效层、分数）；文档列出的配置是 T13-01_无尽主动收获确认。320×568 下拖放命中要与视觉格一致，所有候选可见。
- 依赖：F017、F029。
- 数据/事件：board（坐标键）、tray[3]{shapeId, cells, color}、rngState、score、combo、placements、settled、previous。放置命令 {runId, revision, slotId, anchor}，过期或重复的拒绝。事件 **PlacementCommitted**{新增格, 消线集合, 分数差, revision}。日/周事件只在 F034 有效结算后累计。
- 验收要点：枚举坐标恰好 37 格；越界或重叠时拒绝，候选和随机序列不变；单轴、双轴、三轴交叉同次清除且无残留；用两槽不补牌，第三槽用完恰好发 3 块；同 seed/rngState 冷启后下一轮一致。
- 未知/待定：原型的 **10 种形状**是当前对照集合（具体形状和概率见 prototype/app.js）；扩展形状需要单列数值变更并保证确定性兼容。

### F031 无尽分数连击与本机纪录
- 目标：讲清放置、消线和连击的得分，只保存本机最高纪录；分数与花蜜无关。
- 规则与数值：
  - 放置分：**每格 10 分**。
  - 消线分：一次消 n 条得 **100n**，另加多线奖 **50×n×(n−1)**。例：2 线 200+100，3 线 300+300（放置分另算）。
  - 连击：连续的有效放置每步都有消除才算；任何一步没消除就归零，非法放置不影响连击。
  - **D01 未定（连击加分）**：策划写“第 2 次起加 25×连击序号”，即第 2 次 +50；原型 combo 先 +1 再加 25×(combo−1)，即第 2 次 +25、第 3 次 +50。两种都保留，不能暗选一种发布。
  - 例：消除→不消除→消除，第三步算新的首消，没有连击奖。
  - 规则层先算出可复核的明细，再更新总分。
  - 最高纪录 endlessBest 在结算时取 max。即使低于发币门槛也可以更新纪录，但不发“完成一局”。新局、重开、0 分结算都不会让纪录下降。例：5000 后再结 4000，纪录仍是 5000。
  - 撤回会回滚本局分数，但不改已提交的纪录。
- 页面/弹窗：无独立页面；分数显示在无尽对局页，结算页有三个独立槽：本局分、历史最佳、实得花蜜（T13-01）。
- 依赖：F017、F030。
- 数据/事件：run.score、combo、计分规则版本；放置回执记 cellsScore、lineScore、multiLineScore、comboScore；endlessBest 是玩家纪录。事件 **BestChanged**、**RunSettled** 只由真实结算触发，页面展示或预览值（如 5000）不能触发成就。
- 验收要点：放 1/3/5 格不消线得 10/30/50；2 线得 200+100，3 线得 300+300；连续两次消线的夹具要暴露 +50 与 +25 的差异，D01 签定后锁定预期；重复结算不重复发 BestChanged。
- 未知/待定：D01 确认后要固定规则版本，旧活跃 run 如何处理需要显式迁移。纪录不联网、无排名、无反作弊。

### F032 无尽单局免费撤回
- 目标：每个 run 一次免费撤回，完整撤销最近一次合法放置。
- 规则与数值：
  - 每 run 最多 **1 次**。条件：有最近一次成功放置的 previous 快照，且 undoUsed=false。新局未放、已撤回过、已结算都不能撤回。
  - 恢复范围：棋盘、3 个候选、随机状态、分数、combo、placements、消线结果。如果那一步触发了补牌，也还原到旧轮只剩一槽的状态，不重新抽牌。
  - 撤回后 undoUsed=true、previous 清空；之后再放置也恢复不了资格，重启也不行。undoUsed 不按日重置。
  - 每次成功放置前把 run 复制成单层快照（快照里不含 previous，避免递归增长）。
  - 撤回流程：核对 runId 和 revision→整体替换为放置前快照→保持 undoUsed=true→保存→刷新并重新判断能否放置。保存失败时原局和资格都保持原样。
  - 撤回不涉及钱包，已提交的结算回执不能通过撤回删除。
  - 有效放置次数随快照回滚。例：放 6 次撤回最后一次再结算，最终是 5 次，达不到 F034 的 **6 次有效局门槛**。
  - 撤回会取消上一步未完成的清线、飞字和补牌动画；用新 revision 拦截旧的异步回调。
- 页面/弹窗：无独立页面，在无尽对局页加撤回按钮，显示“本局1次/已使用”和不可用原因。
- 依赖：F030、F031（引用 F034）。
- 数据/事件：run.undoUsed、run.previous（带 revision）。事件 **UndoCommitted**{runId, fromRevision, toRevision}，不算有效局、任务、建设或活动点数。
- 验收要点：双线放置后撤回→交叉清线、分数、combo 全部复原；第三块触发新一轮后撤回→恢复旧轮三槽和原 rngState；第二次撤回被拒，重启也一样；6 次撤回 1 次→结算按 5 次，不满足门槛。
- 未知/待定：无位置弹窗（F033）覆盖棋盘时是否直接露出撤回入口，由交互稿决定。

### F033 无尽无位置与可验证清理方案
- 目标：只在所有剩余候选都放不下时进入结束选择；救局用的清理方案必须可计算、可验证。
- 规则与数值：
  - 判定：每个非空槽遍历 37 个锚点，只要有一块能完整合法放下就能继续。不能因为当前选中的块放不下就判整局结束。
  - 无位置时可以免费结束收获。激励续局完全自愿，每 run 最多 **1 次**（continues ≤ 1）。免费收获和返回不能被广告遮挡。
  - 救局必须先生成一组明确的清理坐标，模拟清理后证明至少有一个候选能合法放下（给出见证 slot/anchor）。没有可验证方案时不展示续局；不能先随机清盘再判断。
  - 流程：放置、撤回、恢复之后都检测→无位置进入 endless-revive→展示当前局和拟清理区域（与实际坐标一一对应）→玩家选免费收获或看广告续局。点续局时重新校验 runId、revision、continues 和方案；拿到 F052/F055 的真实成功回执后应用同一方案，原子存档后回到棋盘。
  - 广告取消、失败或无填充：棋盘不变，不消耗次数，仍可收获。迟到的回执不能清理另一局；同一回执重复到达最多清一次。
  - 续局不额外加花蜜，不加候选，不改随机状态。
- 页面/弹窗：endless-revive（T12-01_无尽无位置续局），棋盘预览沿用对局页几何。
- 依赖：F030（广告事务见 F052、F055；收获见 F034）。
- 数据/事件：run.continues；方案 {planId, runId, revision, clearCells, witnessSlot/anchor}；广告请求绑定 planId 和 originRun。事件 **EndlessRevived** 按回执去重，不算放置、计分或有效完成。
- 验收要点：A 放不下而 B 能放时不弹无位置，B 可正常放；全部放不下时显示结束选择，免费收获可点；用见证 slot/anchor 重新校验结果为 true；没有可验证方案或已续过一次时续局不可用并说明原因。
- 未知/待定：清理区域的视觉表现以原稿为准。原型 revivePlan 只返回“第一个能落在盘内的形状所占的已填格”，生产必须加见证验证；广告平台接入和额度见 F052/F055。

### F034 无尽主动收获与花蜜结算
- 目标：无尽模式支持可取消的“主动收获”，每局只结算一次花蜜；分数、实得花蜜、任务有效局三者分开计算。保存后继续不结算，免费结束不需要看广告。
- 规则与数值：
  - 流程：点收获→endless-confirm（取消则回同一run，候选块和随机状态都不变）→确认后进入endless-result。
  - 基础毛额 = min(120, floor(score/100)×5)；单run最多120；每日基础无尽累计最多240。
  - 当前可发 = max(0, min(毛额−该run已发, 240−当天已发))。
  - 不足100分时毛额为0，但仍可刷新本机最佳纪录。
  - 有效任务局：最终 placements≥6 且 score≥100，按runId只计一次。
  - 结算顺序：核对活跃run/revision→统一结算命令读取run回执和当日额度→算实得→原子保存钱包、每日累计、纪录、有效事件、run.settled→显示结果。
  - 结算后不能再放块。重复确认返回原回执；续局或恢复不会二次结算已发部分；失败可以重试，不能出现“settled已写但奖励漏发”。
  - 追加广告奖励走F056，不占基础额度。
- 页面/弹窗：endless-confirm、endless-result；T13-01 无尽主动收获确认、T14-01 无尽成绩结算；通用确认弹窗、奖励条目。
- 依赖：F019、F020、F022、F030、F031（另：F056 广告追加）。
- 数据/事件：endlessReceipts[runId]{honey, placements, counted}、endlessDaily、dayKey、run.settled。有效结算时发一次RunCompleted；累计摆放只补 max(0, 最终placements−此前已记placements)，以撤回后的真实摆放数为准。结果含score、best、baseGranted、receiptId。
- 验收要点：
  - 分数99/100/2400/3000，毛额分别为0/5/120/120。
  - 当天已发235、本局毛额120→实得5；当天已发240→实得0。
  - 同run确认两次、冷启动后重放：钱包和任务都只计一次。
  - 5摆200分、6摆99分都不计有效局；6摆100分计1次。
- 未知/待定：D02——“有效局≥6摆且≥100分，花蜜按有效得分”这句话也可以理解为门槛同样限制发币。原型app.js先按分数发币，门槛只限制任务事件（5摆200分会发10花蜜但不计局）。需要决策。

  - 先落盘，再调用 Adapter；重试沿用原 pending 身份。
  - 回执按原 profile 和快照处理：奖励、成功计数、冷却时间、消费键在一次 durable commit 中写入，之后才 ACK 原生队列。重复回执返回既有结果。
  - 归属未知的回执隔离：不发奖、不 ACK。
  - 迟到回执不能给新局加步或清盘；原局的恢复记录单独保存。

- 未知/待定：跨日时成功额度算请求日还是确认日未定（等 F022 和平台回执契约冻结），两个日期都要保存；禁止各处临时用 Date.now 计数。

### F062 四尺寸适配与易用性收口

## 4. 存档数据模型（汇总）

所有内容保存在**一个**玩家档中（F017），用一个信封包住，事务原子提交。下面字段名沿用策划中的建议名和原型名，可以改名，但语义必须保留。

```text
Envelope {
  schemaVersion, profileId, revision(单调递增), savedAt(来自 durable commit), checksum/提交标记
  payload: {
    meta:      { createdAt, contentVersion/catalogVersion, migratedFrom?, initialGrantDone(新档120H/5h只发一次) }
    wallet:    { honey: 非负安全整数, hint: 非负安全整数 }     // F019，只能通过 grant/spend 命令修改，不提供 setBalance
    mainline:  { mainlineVersion, reachableLevel(1..96), mainlineCompleted:bool, selectedMainline, mapPage(1..12),
                 completedLevelIds:Set<稳定题ID>,                 // 首通按稳定题ID去重（classic-xxx / challenge-xxx）
                 bestStars: { [challengeLevelId]: 1..3 } }        // F015，只增不减
    attempts:  { active?: {                                        // F013，当前活跃拼图局
                   attemptId(冷启后也不碰撞), levelId, mode, placements:{pieceId→translation}, placementOrder:[pieceId],
                   moves, status(playing|completed|failed), hintsUsed, hintTarget?{pieceId,translation,boardRevision},
                   continuesUsed(0..1), revision },
                 receipts: { [attemptId]: {firstClear, honey, stars, settlementId, eventId} } }   // F020 attemptReceipt
    endless:   { activeRunId?, runs/active: {
                   runId, seed, rngState, board:{"q,r"→color}, tray[3]:{shapeId,cells,color}|null, score, combo,
                   placements, undoUsed, previous?(单层快照，不含 previous), continues(0..1), settled, revision },
                 endlessBest, runsCreated/settledCount(决定前2局种子 20261016/20261017，口径待定),
                 receipts: { [runId]: {honey, placements, counted, receiptId} },
                 daily: { dayKey, honeyGranted(≤240) } }
    garden:    { chapter(0..2), buildings[5](0..5, 当前园), chapterClaims:{0,1,2}(领取键 chapter:{c}),
                 chapterFinished(派生缓存), lastCommandIds }
    collection:{ photos:Set<0..17>(含来源回执), albumClaims:{0,1,2},
                 ownedOutfits:Set<0..4>(0始终拥有), selectedOutfit,
                 selectedBee(0..2), affinities[3](0..30), affinityToday{dayKey,used≤3},
                 companionDecorations[3]:bool, storyReadIds?(仅已读标记) }
    periods:   { lastAcceptedDayKey, weekKey(周一),
                 daily: { dayKey, dailyPlays, builtToday, dailyPlacements, dailyPuzzleCompletions, featuredCompleted,
                          featuredList[≤3 稳定题ID], featuredDone, repeatClaims(0..5), processedEventIds },
```

### 5.2 已核清的结论（不要再误判）
- 限步首通固定 120，不叠加当次 1–3 星 × 20；之后提高最佳成绩才按每星 20 补差额。普通首通 80；复玩 20，每天 5 次。
- 正式题库缺 `perfectMoveTarget` 字段，三星阈值不能用 moveLimit 代替。16 个主线限步关的值如下：
  - 限步 1–5：完美 4 步，预算 7
  - 限步 6–10：完美 5 步，预算 8
  - 限步 11–15：完美 5 步，预算 7
  - 限步 16：完美 6 步，预算 8
- 日任务、签到、活动的预览奖励不代表玩家已持有，所有领取都要先保存再显示。
- 历史上的"缺少"目录标签不代表素材缺失。
