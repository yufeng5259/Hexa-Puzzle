## 0. 结论速览

| 项目 | 结论 |
|---|---|
| 规模 | 共801个文件、767 MB。**运行时 PNG 372 张（121 MB）**，清单登记371张，另有1张未登记的 `页面素材/主图/title.png`。其余约 640 MB 是预览和对照图（效果预览、页面对照、设计板），不进游戏包 |
| 页面覆盖 | 79张页面／状态都有效果图和图层级页面配置：9张原始基稿，加上“缺少”目录里70张补图（T01～T51）。另有4张素材设计板：三园五建筑0～5级，以及棋子／托盘材质 |

**命名规范**
- 运行 PNG 文件名为 `<中文语义名>_<rgba_sha256前10位>.png`，例如 `下一关按钮_95161f55c5.png`。实际加载应以 `素材清单.json` 里的 canonical `id` 为准，例如 `block_background_主图`、`block_玩法_粉色花朵蜂窝`。旧 id 作为别名保存在 `identities` 和 `retired_duplicate_ids` 中，页面配置里有65处图层引用的是别名，通过 `master_asset` 都能解析到；全部3157个图片层的文件都存在。
- 建筑命名为 `<园名>_<建筑>_<0-5>级_原生母件`。小溪水车1～5级拆成两张：“无轮静态本体”和“独立水轮转子”，转子可以单独旋转。
- 棋子命名为 `<颜色>无花母件`（未落地）和 `<颜色>落地母件`（落地后开花），共5色：金、蓝、粉、绿、紫。
- 页面目录有两种：原始9页用中文页名（其中 `微信图片_20261019173444_81_187` 实际是**当前主界面／拼图地图**，路由为 `levels`）；补图页用 `Txx-yy_<名称>`，Txx 是任务号，yy 是同一任务下的状态序号。
- “缺少”目录的含义：**原本缺少、这一轮已经补完的页面**，不是未交付。真正没交付的内容见第3节。

**页面配置 JSON 的内容（能否拼 Prefab：能）**
- 顶层字段：`page, size/canvas [853,1844], coordinate_system`（“像素；左上原点；z由底到顶；anchor为资源左上角归一化坐标”）、`layers[], texts[], localization, comparison`；补图页另有 `runtime{}`、`art_direction`、`source_reference`、`prototype_reference`。
- 图片层字段：`asset/id/master_asset, file, position[x,y]`（alpha 裁紧后的左上角坐标）、`size, native_size, scale, anchor, z, opacity, visible, group`，以及 `render_transform{source_crop?, resize, nine_slice{insets:null}?, rotate?, alpha_crop}`，`metadata.target_box/fit/state/parent`。
- 文字层：`text, box[4], font_size, min_font_size, max_lines, color_rgb, stroke_width/color, align, weight, font: 微软雅黑 (msyhbd.ttc), localization_key, value_binding, text_role (message/number/template/player_input), overflow_policy`。**除封面 “Honey Garden” 标题外，图片里没有烘焙任何文字**，可以直接对应 Cocos Label。
- `procedural` 层（共100个）：`renderer:"block.hex.v1"`，含 `cells[[q,r]...]`（轴坐标）、`role`（floor/rail/shadow/well/hint/obstacle…）、`bbox, padding, supersample, procedural_crop`。棋盘外形、木边、内孔、投影、金色提示轮廓、固定障碍“×”都按数据生成，不另出PNG。
- 玩法页的 `runtime` 字段含 `board_state`（每颗棋子的 asset 和中心点）、`grid_centers`、`runtime_shapes[].cell_centers_local`，可以直接作为关卡和棋盘布局的样例。
- 注意：九宫格层只标了 `nine_slice`，**`insets` 一律为 null**，需要在 Cocos 里手工设置 border。坐标基于 853×1844 设计画布，导入时按 Canvas 的设计分辨率换算，并把 y 轴从左上原点翻转为 Cocos 的坐标系。

## 4. Cocos 运行时技术评估

### 4.1 尺寸统计（运行 PNG，372 张）
| 尺寸档（长边） | 数量 |
|---|---|
| ≤256 | 107 |
| 257–512 | 162（含107张建筑512×512） |
| 513–1024 | 39 |
| 1025–2048 | 63 |
| >2048 | 0 |

- 全部是 RGBA（color type 6），只有两张地形是 RGB。267 张不是2的幂（NPOT），对 Cocos 自动图集没有影响，但单独使用时不能生成 mipmap。
- 按类别统计体积：全屏背景和地形12张共 35.8 MB（每张 2.6～3.3 MB）；建筑107张 22.0 MB；棋子母件10张 9.1 MB；角色和装饰插画24张 15.2 MB；其他UI和图标210张 38.7 MB；遮罩9张 0.1 MB。**合计 121 MB**。
- 全部解码成 RGBA 约需 **488 MB** 显存或内存，不能一次性加载。

### 4.2 超尺寸贴图
70件资源的最大显示尺寸不到原图的50%（以 853 宽设计稿为准）。典型例子：
| 资源 | 原图 | 设计稿中最大显示尺寸 | 比例 |
|---|---|---|---|
| 金色星级母件、灰色星级母件 | 1123～1138 px | 约44 | 4% |
| 10张棋子母件 | 1073～1195 px | 50～145 | 5～13% |
| 场景蜜蜂（花园、工坊、水车、树屋、温室） | 约1100 px | 66～143 | 6～12% |
| 侧栏入口图标（每日签到、好友、礼包、活动、每日任务） | 约1000～1200 px | 约135 | 11～12% |
| 金色和灰色关卡盾牌母件 | 约1150～1240 px | 134～146 | 12% |
| 8份头像空白等级 | 约500～600 px | 约150 | 25% |
| 每日签到红点 | 280 | 35 | 13% |

建议：用脚本按“设计稿最大显示尺寸×1.5”（适配 1080～1290 宽的真机）降采样。像素量可以从 128 Mpx 降到约 25～50 Mpx，棋子单格降到约 160～192 px 足够用。降采样后的源图另外保留在美术仓库里。

### 4.3 九宫格
页面配置中标记了 nine_slice 的资源：透明计数底条(224×65，使用140次)、空待放托盘(820×317)、下一关和再来一次按钮(496×147)、3种空白主面板(684×883、727×1207、731×1206)、赠送进度槽和填充、页签背框、选中和未选中页签、好友行底板、进度填充。
- 这些都是规整的圆角木框或果冻按钮，**适合九宫格**。空白主面板左上角有一片叶子，border 留够就不会被拉伸。3种主面板可以合并成1张九宫格。
- **insets 都是 null**，需要在 Cocos 里逐张手动设置 border。
- 结算红飘带、木牌标题、带吊绳的木牌这类带装饰的，不适合九宫格，保持原样即可。

### 4.4 自动图集建议（Cocos Auto Atlas，最大 2048×2048）
- **适合进图集**：降采样后的公共UI（按钮、底条、图标、角标、勾、锁）、棋子单格（10张，每张约192 px，一张图集放得下）、消除粒子、货币和道具图标。按模块分：`common_ui`、`puzzle`、`home_ui`、`meta`（相册、成就、衣柜）。
- **不进图集**：853×1844 的背景和地形（单独纹理，转 JPG）、标题插画、大立绘。建筑母件 512²：每园35张，降到 320～384 后每园1～2张 2048 图集，或者单图按需加载。
- 应在小游戏和 Android 上实测 draw call。木框、凹槽这类 procedural 棋盘层建议在开局时生成一次 RenderTexture，或用 Graphics/Mesh 绘制（参考 `运行组件/block_hex_runtime.js` 移植）。

### 4.5 包体与微信小游戏限制
- 微信小游戏限制：**主包 ≤4 MB，主包加分包总计 ≤30 MB**（旧限制是20 MB）。现有 121 MB 的 PNG 直接打包**完全不可行**。
- 粗略估算处理后的体积：
  - 背景和地形12张转 JPG（q80），每张约 250～400 KB，合计 3～5 MB；
  - UI 和图标降采样后用 pngquant 或 TinyPNG 压缩，约 4～6 MB；
  - 建筑107张降到 ~320 px 并量化，约 4～6 MB；
  - 角色和插画约 2～3 MB；
  - **合计约 13～20 MB**，可以放进 30 MB 总包，并给音频留 3～5 MB（BGM 用单声道 64～96 kbps 的 mp3 或 m4a）。
- **推荐策略（单机、不用CDN）**：
  1. 主包只放引擎裁剪后的代码、首屏小 Loading 图（≤150 KB JPG）、少量通用UI，总量控制在 4 MB 以内；
  2. 分包划分：`core-puzzle`（玩法、无尽、结算、通用UI、棋子）、`home-garden1`、`home-garden2`、`home-garden3`（各园地形和建筑）、`meta`（相册、蜂友、活动、成就、设置、帮助）、`audio`；
  3. 不用远程CDN资源，全部内容随包分发，进入相应场景前用 `loadSubpackage` 预加载；
  4. Android 包没有体积限制，但应复用同一套降采样资源。可选 ETC2/ASTC 压缩纹理来降低内存，微信端可在 iOS 上用 ASTC，或者保持 PNG/JPG；
  5. `页面对照/`、`效果预览/`、`素材设计板/`、`index.html` 不进包。

### 4.6 适配
- 设计画布是 853×1844（约 0.463，相当于19.5:9）。建议 Cocos 设计分辨率用 853×1844 或 750×1621，按宽度适配。在 16:9 机型上，全屏背景采用 cover 裁剪，上下各损失约 9%。背景安全区内没有关键内容，但顶栏和底部按钮需要用 Widget 吸附刘海和底部安全区。

## 5. 美术风格描述（供新需求对齐）

- **题材**：Honey Garden，田园蜜蜂花园，休闲六角拼图加家园建设。三个主题园：向阳花园（暖阳、木屋、花圃）、清风水湾（溪流、水边、蓝绿）、云上蜂谷（高处云雾、山谷）。
- **画法**：明亮饱和的2.5D厚涂或卡通渲染，接近手游“梦幻花园”一类。光线柔和、偏暖，从左上照来，边缘有高光，阴影偏暖棕。建筑用3/4等距俯视视角，造型圆润，带体积感和细节（藤蔓、小花、灯笼、木桶）。
- **配色**（近似值）：
  - 主色：蜂蜜金 `#F8C232`～`#FFB000`，原木棕 `#A8642A`（木框）和深棕 `#5A3A1E`（棋盘凹槽底色 `#4A3626`），奶油羊皮纸面板 `#FFF1D2`；
  - 辅色：叶绿 `#5DBB3A`（主行动按钮）、天蓝 `#3FA0F0`（次级按钮）、飘带红 `#E8505B`、紫 `#8A4FE0`（无尽模式）；
  - 棋子5色：金 `#FFC928`、蓝 `#1E8CF0`、粉 `#F2629A`、绿 `#5CC83A`、紫 `#8340E0`。
- **UI 语言**：木纹板和木牌标题（挂麻绳，两侧点缀花叶），奶油色圆角面板配厚木边框，果冻或糖果质感的胶囊按钮（顶部白色高光，深色描边），圆形木质图标按钮，深色半透明胶囊计数条，红色飘带标题，金色五角星，金色和灰色六角关卡盾牌。
- **字体观感**：粗圆黑体。标题是白字配深棕描边，正文是深棕字放在奶油底上，数字粗大。
- **角色**：Q版拟人蜜蜂，大头圆眼，腮红，笑脸，部分戴飞行护目镜。主角小蜜戴晴天围巾，花花抱花盆，阿工系围裙、拿锤子。配角是白鸭。
- **棋子**：立体倒角的果冻六角块，未放下时是素面，落地后浮出五瓣花纹和中心小花（金色橙花、蓝色白花、粉色红花、绿色四叶草、紫色白花）。棋盘是深棕凹槽加浅木色描边。
- **新素材要求建议**：保持相同的3/4视角和左上光源；描边用深棕色而不是黑色；高饱和但不刺眼；花叶点缀；不烘焙文字；交付 PNG 原生母件时同时给出用于游戏内的推荐尺寸（例如棋子192 px、图标≤256 px、建筑≤384 px）；全屏背景不要带UI。
