# 01 现状分析

> 历史方案（2026-11-03）：本次五页首版以 [当前入口](README.md) 的三份文档为准。下方现状结论保留当时基线，不能据此清空当前已存在的framework或恢复旧全量任务。

完整报告见 [分析报告/](分析报告/)。本文只列影响决策的结论。

## 1. 游戏本身

**Honey Garden**：竖屏单机休闲游戏，主题是蜜蜂家园。核心是六边形拼图，配合家园建设。

### 核心循环

```
Loading → 主线地图（唯一主界面，12页×8关）
  → 开局预览 → 拼图局（普通 / 限步）→ 结算得花蜜 → 下一关 / 回家园
  → 家园：花蜜直接升级建筑（3园×5栋×5级，共75次升级，总价8800花蜜）
  → 一园 25/25 满级 → 完工奖 → 下一主题 → 第二园 → 第三园
  → 三园全部完成 → 进入回流玩法（精选复玩、无尽纪录、相册、蜂友故事）
```

### 玩法模式

| 模式 | 规则 | 产出 |
|---|---|---|
| 普通拼图（80关） | 异形块只平移、不旋转；整块合法才吸附；填满目标格即胜；无失败 | 首通80花蜜，复玩20 |
| 限步拼图（16关） | 每6关出现1关；步数7或8；用完即失败，可免费重试；1–3星 | 首通120，星级提升每星补20 |
| 无尽（37格） | 每轮发3块，三个方向整线消除，计分加连击；每局可撤回1次；可主动收获 | min(120, floor(分/100)×5)，每天上限240 |

### 外围系统

- 蜂友3位，亲密度上限30，里程碑在5、15、30。
- 相册3册共18张照片；衣柜5件外观。
- 每日3项任务，每周目标，七日签到，3项成就。
- 野餐活动，本地信箱，5项设置，图示帮助。
- 7步新手引导；5个激励视频广告位。

完整数值见 [C_策划设计摘要](分析报告/C_策划设计摘要.md) §1.5。

### 效果图里有、但设计上已经砍掉的内容

原始9张效果图中的体力爱心、排行榜、好友赠送、商店、背包、超值礼包、新手礼包、步数限制页签和“关卡选择”页面都**不做**。策划已改为：单机、本机纪录、三位蜂友。

## 2. 现有 Hexa-Puzzle 工程

| 项目 | 情况 | 结论 |
|---|---|---|
| 引擎 | Creator 3.8.8，已有微信和 web 构建模板 | 继续使用 3.8.8 |
| 脚本 | 114 个 `.ts` 共约4700行；约75个是生成的空壳 View | 丢弃 |
| Prefab | 82个，由 node 脚本从原型设计层生成，单向，在 Creator 里改过就不能再生成；输入目录 `../prototype/` 已不存在 | 丢弃，重新制作 |
| 导航与启动 | `UIFlow`、`FoundationBoot` 是一个大 switch，写死了 96、12 等数字 | 丢弃，改用 BigHero 的 UIManager |
| 题库 | `level-catalog.json` 共110题：80普通，30限步（其中14题为储备题），已校验无重复 | **直接复用** |
| 纯逻辑 | `HexCoordinates`、`LevelDefinition`、`LevelCatalog`、`PuzzleModel`、`PuzzleSession`、`PuzzleLayout`（约450行） | **直接复用** |

| 无尽 | 只有空页面，没有逻辑 | 新写 |
| 存档 | 只存在内存里，重启就丢 | 新写 |
| 资源 | 562张 PNG 共145MB，没有图集，棋子用约1100px的原图缩到50px显示 | 全部重新导入 |
| 引擎模块 | 勾选了 spine、dragonbones、box2d、tiledmap、video、webview，但都用不上 | 裁剪 |

## 3. BigHero2415 框架

- **引擎**：Creator **2.4.15**，TS 代码共919个文件。它是一个已上线 2.x 游戏的可读化重写，里面兼容层很多。
- **启动**：单场景。依次加载配置、语言、建 UI、注册控制器，最后进入登录步骤。
- **UI 管理器**：`ViewCoordinator` 负责分层（Scene/Main/Panel/Popup/Tips/Guide/Loading）、页面互斥栈和弹窗排队。页面基类是 `ViewComponent`，有8个生命周期钩子，过渡期间屏蔽输入，关闭时自动释放资源。
- **Prefab 范例**：
  - `energy_purchase.prefab`：根节点挂 View 组件，`@property` 绑定节点，按钮事件在 Prefab 里绑定。
  - `game_catalogue_view.prefab`：`ScrollableItemGrid` 虚拟列表，cell 做成独立 Prefab。
- **可以原样复制的**（约40个文件，不引用 `cc.`）：事件总线、Timeline 定时器、对象池、配置表、LZString、随机数、`JsonRecord` 存档、物品仓库、列表纯算法、本地化核心。
- **需要按 3.x 改写的**：`ViewComponent`、`ViewCoordinator`、过渡动画、`PopupView`、`ScrollableItemGrid`、`ResourceLoader`、`AudioService`（3.x 已删除 `cc.audioEngine`）、`RewardedVideoButton`、GM 面板。
- **不复制的**：
  - 组合根，以及遍历整棵节点树、按 `instanceof` 注入依赖的做法；
  - 旧路径映射、对 `cc` 原型的扩展、2.x 自定义渲染；
  - 各渠道 SDK、网络、打点、全部业务代码；
  - 所有 2.x 的 `.prefab`/`.fire`/`.meta`。
- **缺的**：Android 返回键处理（需要新增）。

## 4. 美术

- **进游戏包的部分**：`arts/游戏素材/PNG` 共372张，121MB。其余约640MB 是效果图和对照图，不进包。
- **79个页面/状态都有效果图和页面配置 JSON**：每层都有坐标、尺寸、z 序、锚点，可以直接作为拼 Prefab 的依据。除封面标题外，图片里没有烘焙文字。
- **棋盘不出图**：木框、凹槽、提示轮廓、障碍格由 `block.hex.v1` 按格子数据程序生成，`运行组件/` 里有参考实现。
- **素材齐全的部分**：3园×5栋×0–5级共90种建筑造型；5色棋子，每色有“无花”“落地”两种母件；主要 UI 件。
- **超尺寸**：70张图的实际显示尺寸不到原图一半，例如星星原图1100px，只显示44px。全部加载约需488MB 内存。
- **缺失**：
  - 音频、可商用字体、应用图标、分享图、启动图；
  - 清风水湾整屏地形；
  - 约13张相册照片；
  - 一批图标：开关、视频、空星、成就徽章、转圈等；
  - 动效素材；
  - PSD 源文件（只有 PNG 和 JSON）。

  详见 [05_美术需求](05_美术需求.md)。

## 5. 主要风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 微信包体：主包不超过4MB，总包不超过30MB | 原图放不进 | M0 搭美术处理流水线：按显示尺寸×1.5降采样，量化压缩，背景转 JPG，按模块分包；目标总资源不超过20MB |
| 原型目录缺失 | 无尽的10种形状、每日精选算法、剧情台词都没有来源 | 在 06 中给出默认方案，由策划确认 |
| 我无法操作 Creator 界面 | Prefab 需要在编辑器里检查和微调 | 见 06 的 E03：做一个编辑器扩展，从页面配置生成 Prefab 骨架，你在 Creator 中检查确认 |
| Android 广告 SDK 和微信广告位 ID 未定 | 影响 M5 | 先用模拟广告服务跑通流程，SDK 后接 |
| 9个规则冲突项（D01–D09） | 影响对应功能的实现 | 见 06，每项都有默认方案 |
