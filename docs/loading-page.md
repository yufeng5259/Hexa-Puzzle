# Loading 单页处理

本次按现有人工制作的 `LoadingPage.prefab` 接入启动流程。

## 范围与顺序

1. 先运行现有绑定、View 生命周期回归，记录旧 Loading 断言失败；补充单页绑定与启动成功、失败、销毁时异步迟到的回归。
2. 保留背景、标题、进度条和文字的六节点结构，移除旧多状态及原稿展示组件；根尺寸统一为 853×1844，保留进度条当前位置。
3. `LoadingPageView` 直接继承 `BaseView`，仅绑定 `ProgressBar` 与 `Label`，提供进度更新方法。加载职责继续属于 `FoundationBoot`。
4. Loading 改为人工维护，生成器保留资源登记但不重建脚本与 Prefab；其他页面保持现有生成与验证规则。
5. 运行回归、TypeScript、资源审核和现有 Creator 的真实导入/启动预览，分别记录静态与实际画面证据。

## 进度与失败

进度表示配置、题库、首屏准备等启动阶段，不表示下载字节比例。首屏准备成功后完成进度并切页；失败保持 Loading，使用现有提示显示错误。页面关闭或启动组件销毁后，不再写入 Loading。

## 验收

- 0%、50%、100% 的条与文字一致；缺少绑定明确报错。
- 不再存在状态数组、SourceLayout 或 PresentationGroup 依赖。
- 首屏失败不报就绪、不完成到 100%，迟到结果不会更新已关闭界面。
- 保持既有 UUID 和人工布局；不恢复任何已删除资源，不重建其他页面。

## 本次验证结果

- `npm test`：216 项通过；销毁防护调整后，重新运行 Loading 的 10 项回归及 TypeScript 检查，均通过。
- Creator 3.8.8：复用现有 7456 预览，在独立浏览器内加载 Main，成功进入主线地图；打开人工 Loading 后实测 0%、50%、100% 的填充宽度为 0、295、590，缺绑定校验和重复显示隐藏通过。
- 已检查 320、390 宽的六张实际 Canvas 截图；背景、标题、条与百分比显示正常。销毁后调用更新方法不会访问已被引擎清空的字段。
- 原生证据：`../../tmp/prototype/prefab-foundation/loading/native-report.json`；截图及可重跑的 `verify.cjs` 同目录。报告状态为 `PASS_NATIVE_LOADING`，页面错误和资源请求失败均为 0。该证据针对 Loading 与 Main 启动，不表示全项目原生验收通过。
- 全项目 `npm run audit` 仍失败：公共 `ProgressDisplay` 引用原有进度底槽/填充 UUID（`db4cfcad…`、`18d78651…`），这些旧文件在本次修改前已被删除；原稿清单也仍记录七个已删除或重命名的旧 boot 图片路径。本次未恢复旧文件、修改公共进度条或放宽审核断言。新 Loading 的四个 SpriteFrame 引用均存在。
- 原有全量原生验证脚本在本机 Chrome 启动时退出；本次专项验证使用现有 Edge，真实运行同一 Creator 引擎。
