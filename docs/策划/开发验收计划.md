## 每项功能的最小验证包

1. 记录功能ID、原策划版本/哈希、实际修改文件、源代码与资源指纹、测试命令/版本和结果。验收记录写清“已执行/未执行/失败”，不只粘贴预期。
2. 针对该功能新增或改变的规则做定向测试；事务类覆盖重复、乱序、写失败、进程重启和并发。现有规则测试可复用，不为文档改动新增无意义业务测试。
3. 涉及引擎装配、Prefab、引用、导航或可视交互时，在Creator 3.8.8实际导入/实例化并操作；无新增页面的数据功能，也验证启动装载或真实业务调用点。静态JSON和模拟引擎测试不足以替代此项。
4. 有界面变更时提供原稿/PSD合成/Creator实屏三列和真实操作记录；说明动态数字及批准差异，不能使用大面积遮罩掩盖布局差异。纯数据功能可注明无直接视觉变更。
5. 保存加载失败、重试、未加载完关闭、重复显示隐藏、快速切页、异步迟到、必需绑定缺失与资源释放证据；只运行受影响项，但最终阶段覆盖所有生命周期场景。
6. 共享层改变后运行当前 `npm test`、`npm run typecheck`、`npm run audit`；使用[当前package.json](../../package.json)，不把旧`test:legacy`结果当新框架通过。按改动运行实际需要的`prefab:verify-native`、`ui:verify-native`、`levels:verify-native`、`play:verify-native`，不能在同一Creator/预览端口上并发互相覆盖。
7. 涉及平台的功能另附真实SDK/真机证据；缺账号、设备或签名则登记阻塞，不用模拟结果升级整项状态。局部未验不阻止独立本地分支继续开发。

测试临时输出位于`tmp/prototype/<实施任务>/`；正式最终画册与验收记录位于唯一原型的`prototype/review/`，由所属实施任务建立明确命名目录。不得复制完整工程到临时目录作为验收对象。

| 真实Creator端到端 | 实际Prefab绑定、状态与交互、页面栈、scope与迟到、3/4/5/6/7片布局 | 唯一Project导入/实例化/真实输入；同源截图与操作记录，缺绑定直接失败；DOM合成和可信输入分别注明 |
| 平台端到端 | Android/微信SDK、前后台、离线、强杀恢复、硬件取消与真实包GM隔离 | 双端设备记录、SDK/系统版本、包哈希；模拟回调只归协议层，不证明此层 |
| 可观测性 | 定位错误与事务，不泄露配置/玩家正文 | 每笔使用featureId、profile隔离标识、request/attempt/run/settlement/eventId、revision、commit状态、ACK顺序及错误码；白名单日志，不含凭据/完整存档 |

逐阶段将同一条真实事件的来源→候选→持久结果→View表现串起来；既要证明“奖一次”，也要证明写失败“完全没奖”和重启后“能安全补处理”。错误、警告和失败资源原样保留，不能删日志或放宽断言换PASS。

## 团队合入与最终复核

共享存档schema/事务/事件、app装配、注册表及Prefab生成器各指定唯一写入负责人；并行分支只在契约稳定后做独立feature。独立实现者提交范围与证据，集成负责人串行合入并运行当前回归/typecheck/audit；具备条件时运行对应Creator验证，单独验证者复核原策划全部条款、AFF/ADS/MIG与真实业务入口。
