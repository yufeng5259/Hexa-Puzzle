# F032 无尽单局免费撤回

状态：业务未接入。核对日期：2026-10-28。本篇规定后续开发目标，不表示业务或Creator实机验收已完成。

## 目标与依赖

每个无尽run给一次免费撤回，完整撤销最近一次合法放置及其派生变化，让玩家能修正一次判断。不是无限回退、广告商品或仅删一组棋盘格。

前置功能：[F030 37格无尽发牌放置与三轴消除](F030_37格无尽发牌放置与三轴消除.md)、[F031 无尽分数连击与本机纪录](F031_无尽分数连击与本机纪录.md)。范围边界以[功能清单](../功能清单.json)为准，不改已有启动、存档或奖励权威。

## 规则与流程

每run最多1次，需存在最近一次成功放置的previous快照且undoUsed=false。创建新局但未放、已撤回、已结算都不可撤回。恢复必须覆盖棋盘、三个候选、随机状态、分数、combo、placements及消线结果；跨补牌的那一步也还原到旧轮剩余一槽，不重新抽不同牌。撤回后undoUsed=true且previous清空，再放也不能恢复第二次使用资格。

成功放置前将run复制为单层快照，排除快照自身的previous，避免递归增长。点击撤回再次核对runId和revision→完整替换前快照→将撤回消耗标记保持为true→保存→刷新棋盘托盘分数并重判可放。保存失败保持原局和资格；没有独立钱包变更。已提交结算回执不可通过撤回删除。

## 数据、事务与事件

undoUsed是run生命周期字段，不按日重置；previous属于同一个run且记录revision，不能引用上局快照。UndoCommitted携带runId、fromRevision/toRevision仅作业务同步，不计有效局、任务建设或活动点。有效摆放次数必须随快照回滚，F034结算只统计最终留在run中的placements，不能撤回前先把日摆放永久加上。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 可执行验收

1. 新run未放时点击：无快照，状态不变且提示原因。
2. 放置形成双线后撤回：交叉清线全复原、分数与combo复原。
3. 使用第三候选触发新轮后撤回：恢复旧轮三槽状态及原rngState。
4. 撤回一次后继续放置再点：第二次拒绝，重启也不能重获次数。
5. 放置6次撤回最后一次后结算：最终5次，不满足6次有效局门槛。
6. 撤回保存失败后重试：资格与棋盘不能出现一改一未改。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
