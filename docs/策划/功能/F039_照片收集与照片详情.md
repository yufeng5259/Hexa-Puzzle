# F039 照片收集与照片详情

记录家园真实建设里程碑，提供三册共18张照片的获得状态和详情。相册浏览与查看未获照片均不得自动解锁或补写建设进度。

## 规则与流程

每园6张，前5张分别是稳定ID0树屋、1花园、2蜂蜜工坊、3小溪水车、4温室的首次升级照片，第6张是领取整园完工奖励时的合影。photoId=chapter×6+slot，范围0至17。首次0→1时记录建筑照片，之后1→5不重复；合影不是五栋满级立即获得，必须F026成功领奖。已获看实图与来源，未获看占位及准确获得条件。

F023成功升级事务写入对应首建照片→PhotoUnlocked刷新相册；F026成功领奖同次写入合影。相册选园只切metaAlbum上下文，六格按持有状态显示；点格进入album-detail，返回原册。未获建筑照片可去当前家园，未获合影说明全园并领奖；旧园从世界地图进相册不重置当前建设。

## 数据、事务与事件

photos为F017统一去重集合，唯一来源是对应建设/完工事务回执。展示数量按当前册六ID交集计算0至6，不用整个数组长度作为分母。PhotoUnlocked含photoId、chapter、sourceReceipt及时间；重复来源事件不重复加图。照片资产按登记映射加载，不能以文件存在推定玩家拥有，UI浏览索引不写进持有集合。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 组件接入与生命周期

AlbumPageView、PhotoItemView承载三册六格，PhotoDetailView展示照片和来源；F040接集齐按钮。少量六格可Layout，item每次绑定重置锁态、角标、回调和图片请求。GardenAssetStore追溯原稿与派生，章节切换检查photoId/requestRevision，关闭详情解除加载和事件，资源所有权对称释放。

继续复用[UIFlow](../../../assets/scripts/app/UIFlow.ts)导航、[GardenAssetStore](../../../assets/scripts/features/garden/resources/GardenAssetStore.ts)登记校验与所属页面资源边界。稳定引用用Inspector强类型绑定，缺项报错；显示订阅、隐藏解除，销毁取消任务与迟到请求，资源addRef/decRef对称。

## 可执行验收

1. 向阳树屋0→1获photo0，继续1→5仍只有同一张且来源不变。
2. 五栋全5但未领奖：5/6；领完工后恰为6/6并获photo5。
3. 第二、三园首建与合影ID为6至11、12至17，不串第一册。
4. 未获照片详情显示占位与条件，不能展示已收藏标识或写持有。
5. 世界地图回看旧册后返回家园：当前chapter/buildings保持。
6. 快速切册及详情开关：图片、标题、锁态一致，无旧请求覆盖。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
