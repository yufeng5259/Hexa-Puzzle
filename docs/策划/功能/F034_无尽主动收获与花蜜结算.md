# F034 无尽主动收获与花蜜结算

## 目标与依赖

提供可取消的主动收获和一次性无尽花蜜结算，将分数、实得花蜜、任务有效局分开处理。保存继续不结算，免费结束无需广告。

## 规则与流程

主动收获先经endless-confirm，取消回同run；确认后进入endless-result。基础毛额min(120,floor(score/100)×5)，单run最多120、每日基础无尽累计最多240；当前可发=max(0,min(毛额−该run已发,240−当天已发))。不足100分为0但仍可记录本机最佳。有效任务局要求最终placements≥6且score≥100，并按runId只计一次。

确认收获→核对活跃run/revision→统一结算命令读取run回执和日期额度→计算实得→原子保存钱包、每日累计、纪录、有效事件和run.settled→显示结果。重复确认返回原回执，续局或恢复不得二次结算已发部分。结算后不可继续放块；失败可重试，不能先把settled写成功再漏奖。追加广告奖励另走F056，不混入基础额度。

## 数据、事务与事件

F017/F019权威持有endlessReceipts[runId]的honey/placements/counted、endlessDaily及dayKey，F022统一累计事件。有效结算时RunCompleted一次，累计摆放只补max(0,最终placements−此前已记placements)；撤回后的真实摆放数为准。结果字段独立score、best、baseGranted和receiptId。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 可执行验收

1. 分数99/100/2400/3000的毛额为0/5/120/120。
2. 当天已发235、本局毛额120：实得5；已发240再结算实得0。
3. 同run确认两次、冷启动重放一次：钱包与任务只累计一次。
4. 5次摆放200分和6次摆放99分：均不计任务有效局；6次100分计一次。
5. 确认页取消：仍可继续放置，候选及随机状态不变。
6. 事务写入失败重试：钱包、额度、纪录、run终态和事件回执一致。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
