# F035 蜂友解锁列表与跟随

状态：业务未接入。核对日期：2026-10-28。本篇规定后续开发目标，不表示业务或Creator实机验收已完成。

## 目标与依赖

用本地三位蜂友提供陪伴、列表与单一跟随选择，展示真实开放状态。蜂友不是联网好友，不做在线时间、互赠体力、联机排名或收益倍率。

## 规则与流程

稳定蜂友0小蜜“一路同行”、1花花“照料花园”、2阿工“建造能手”；原型beeOpen按chapter≥0/1/2判断个体开放，初始小蜜已认识。列表可查看锁定者来源，选择未解锁者不改变当前跟随；已解锁选择或成长页“一起出发”保存selectedBee。详情浏览metaBee与跟随selectedBee分离，查看谁不等于跟随谁。

从家园进入bee-home→读全体开放状态、亲密与当前跟随→点卡查看或切换→选择合法蜂友后同次保存→列表与家园场景更新。返回保持来源；关掉页面不切回默认小蜜。首园开放门槛与D07统一，不能只放开列表却使活动或地图口径不一。跟随形象不得遮挡棋盘或触控，保留已获外观与专属饰物叠加。

## 数据、事务与事件

沿F017持有selectedBee、affinities[3]、companionDecorations以及章节完成状态；开放状态从统一章节进度派生，不给每个View再写一套unlocked标记。命令校验蜂友ID0至2和开放资格，重复选同一个不产生额外奖励；CompanionSelected事件含old/new ID用于场景刷新，不推进任务。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 组件接入与生命周期

CompanionListPageView接CompanionCardItemView三卡，家园SceneCompanionItemView呈现跟随；类型化绑定角色图、选择状态和按钮，不能运行时拼完整列表。卡片重绑定清除上一个蜂友回调与图请求身份；三项固定少量布局可用Layout，角色异步图按ID验证。隐藏解除选择订阅，销毁释放所属图，不清别的页面资源。

继续复用[UIFlow](../../../assets/scripts/app/UIFlow.ts)导航、[GardenAssetStore](../../../assets/scripts/features/garden/resources/GardenAssetStore.ts)登记校验与所属页面资源边界。稳定引用用Inspector强类型绑定，缺项报错；显示订阅、隐藏解除，销毁取消任务与迟到请求，资源addRef/decRef对称。

## 可执行验收

1. 初始档个体小蜜可认识，花花/阿工锁定且来源说明正确。
2. 只浏览阿工详情：selectedBee不变；未解锁直接提交选择命令被拒绝。
3. 进入第二园选择花花，返回家园/冷启动后仍跟随花花。
4. 先后选择不同蜂友，亲密各自保留，不把当前显示值覆盖其他人。
5. 卡片重复绑定和快速切换：角色图与选择状态不串，监听不叠加。
6. 首园满级、领奖未出发、已出发三档分别记录入口状态，与D07最终决策一致。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
