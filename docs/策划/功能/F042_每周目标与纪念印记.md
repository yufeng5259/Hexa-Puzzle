# F042 每周目标与纪念印记

状态：业务未接入。核对日期：2026-10-28。本篇规定后续开发目标，不表示业务或Creator实机验收已完成。

以每周15局和4天两个并列目标鼓励回访，领取300花蜜及可回看的纪念印记。印记为本地收藏，不是可花货币或战力道具。

## 规则与流程

周以本地日期计算周一作为weekKey。weeklyPlays≥15且activeDays≥4才可领，单满足一项不能领奖；每周唯一weekly:{weekKey}。每次领取固定300花蜜加该周印记，领取历史永久保留，可从已领印记集合按周回看。有效局定义复用F041：真实拼图完成或有效无尽收获，重复run/attempt不加局。

统一日期域检测跨周→更新本周进度→页面分别展示局数与活跃天数→达标主动领→重新核对weekKey与双门槛→钱包、领取键及印记同事务保存→成功可回看。已领按钮打开对应周印记不再发奖；直接请求未获得的历史周详情只显示无收藏。跨周旧弹窗不得把上周资格发成本周奖励。

## 数据、事务与事件

F017/F022持有weekKey、weeklyPlays、活跃日期集合及claims；activeDays应由去重日期集合派生，防一天多次进入累加。历史印记由weekly回执集合推导，metaWeekStamp只是当前选择，不是持有权威。WeeklyRewardClaimed含weekKey、300、stampId、receiptId，任务事件与领取事件分开；周切换不清历史印记或其他终身回执。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 可执行验收

1. 14局4天、15局3天均不可领，15局4天可领300及一枚印记。
2. 同一天登录多次/重复完成事件：活跃最多1天，局数按不同真实回执累计。
3. 领取命令双击、重开和冷启：同周只发300，印记一枚。
4. 查看已获两周印记：展示选中周不改钱包；未获周不得伪装已收藏。
5. 周一边界旧页面点击：必须核对命令周，不按新周凭空补发。
6. 按D06分别构造登录无完成、完成不重复、上周达标未领三档并记录两种策略差异。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
