# F043 七日累计签到礼物

状态：业务未接入。核对日期：2026-10-28。本篇规定后续开发目标，不表示业务或Creator实机验收已完成。

## 目标与依赖

提供累计七日的本地签到礼，不要求连续登录，也不默认循环重开。页面展示每格真实锁定、可领、已领状态，领取动作须与库存同事务。

## 规则与流程

第1至7格花蜜为40/40/60/60/80/80/120，总480；第3、7格各1提示，第7格野餐帽1件。每格signin:{d}终身唯一，d整数1至7；完成第7格保持终态，无第8格、重置循环或强制广告。断一天不清已领取；但“累计日”如何推进漏领格仍有D05，不能把当前行为直接包装成已定补领规则。

日期域打开或恢复时计算当前签到格→页面只展示→点击领取校验格号资格及回执→原子保存花蜜、条件提示、外观持有与领取键→到账后刷新。登录本身不自动发奖励；关闭、后台、冷启不能依赖未完成动画补发。重复请求返回旧回执；第7格帽子去F038实际装备，不能只在文字中说已获得。

## 数据、事务与事件

F017/F022持有signinDay、lastVisit/dayKey及claims，F019库存唯一权威。领取回执包含dayIndex、honey、hintDelta、outfitId与commandId，显示数据从配置获取。原型按rollDay每个新访问日把signinDay+1上限7，不以领取成功推进；生产若采用领取推进或旧格补领须明确迁移，而不是同时保留两套推进字段。

SigninPageView配SigninCellItemView固定七格，按原稿动态Label显示金额与第3/7提示及第7帽子，按钮事件经Controller。重绑定格子清锁态、角标及回调；UI不自行用Date或当前系统天数算可领奖格。show订阅日期与库存，hide解除；销毁取消图请求与庆祝，不影响已保存领取事务。

## 可执行验收

1. 逐格正常领取七次：总480花蜜、2提示、1野餐帽，衣柜可装备。
2. 同格双击、重开及冷启动重放：只领一次，不能重复第7帽子奖励。
3. 未到第7格直接提交第7请求拒绝，库存与回执不变。
4. 断一天后再访问：已领奖格保留，不连续登录也不清空七日进度。
5. 第7格领完再跨日：保持终态，不出现循环或signin:8。
6. 登录第1日未领、下次访问已第2格：分别记录当前原型旧格不能补领与待定策略，决策后锁定预期。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
