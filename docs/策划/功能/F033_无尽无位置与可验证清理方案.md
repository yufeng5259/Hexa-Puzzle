# F033 无尽无位置与可验证清理方案

状态：业务未接入。核对日期：2026-10-28。本篇规定后续开发目标，不表示业务或Creator实机验收已完成。

## 目标与依赖

仅在所有剩余候选确实无位置时进入结束选择，并让救局清理方案可计算、可展示、可复核。免费收获和返回不被广告遮挡。

## 规则与流程

对每个非空槽遍历37个锚点，任一完整拼块可合法放置即仍可继续；不能以当前选中块放不下判整局结束。无位置时可结束收获，激励续局为自愿且每run最多一次。救局必须先生成指定清理坐标集合，模拟清理后证明至少一候选有合法位置；无可验证方案不展示可用续局承诺。不得随机清盘后才判断。

放置/撤回/恢复后检测→无位置进入endless-revive→展示当前局与拟清理区域→玩家选免费收获或广告续局。点击续局时重新校验runId、revision、continues及方案；经F052和F055真实成功回执后应用同一方案，原子存档后回棋盘。取消、失败、无填充维持原棋盘，仍可收获；迟到回执不得清另一局。

## 数据、事务与事件

run.continues为已成功使用次数，最多1；方案含planId、runId、revision、clearCells、witnessSlot/anchor。规则端验证清后合法性，广告请求绑定planId和originRun。清理成功事件EndlessRevived与回执去重，不当作放置、计分或有效完成事件；不额外添加花蜜、候选或随机变更。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 组件接入与生命周期

EndlessReviveView接收证明后的方案摘要与可用资格，棋盘预览沿EndlessPageView几何；广告事务由F052/F055负责，本篇只负责规则证明及呈现。清理范围不能只是美术亮圈，要与实际坐标一一对应。关闭弹窗解除监听但不丢run，资源由所属scope释放；清理回调验证存活和请求身份。

## 可执行验收

1. 候选A无位而B可放：不能弹无位置，且B可正常放下。
2. 全部候选无位时显示结束选择，免费收获可触达。
3. 给定清理方案，模拟后以见证slot/anchor重新合法校验为true。
4. 无验证方案或已经续局一次：续局不可用且解释原因。
5. 广告取消/失败不改棋盘、不消耗成功次数，仍可结束。
6. 同成功回执两次及旧run迟到回执：最多清一次，不能清新局。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
