# F038 专属装饰与外观衣柜

状态：业务未接入。核对日期：2026-10-28。本篇规定后续开发目标，不表示业务或Creator实机验收已完成。

## 目标与依赖

把已获得的外观与蜂友专属饰物变成真正可见、可保存的装配结果。只做本地衣柜和成长装饰，不做商店、抽取、付费购买或属性加成。

前置功能：[F017 持久化玩家存档与写失败回滚](F017_持久化玩家存档与写失败回滚.md)、[F035 蜂友解锁列表与跟随](F035_蜂友解锁列表与跟随.md)、[F036 亲密度成长与里程碑](F036_亲密度成长与里程碑.md)。范围边界以[功能清单](../功能清单.json)为准，不改已有启动、存档或奖励权威。

## 规则与流程

衣柜固定5件：0晴天围巾初始、1野餐帽签到第7格、2花朵帽第1册相册、3水湾丝带第2册、4云朵胸针第3册。未持有可预览并去准确来源，不能装备；已持有选择后保存selectedOutfit。每蜂专属饰物在自身亲密30且已解锁后可戴/取，装配状态独立；跟随别的蜂不删除前蜂饰物。

衣柜选择卡片只更新预览，点使用再次校验持有来源→保存装备→角色预览与家园跟随同步。未持有帽子去签到，另外三件去对应册，返回仍保持浏览上下文。专属装饰页校验beeId与亲密30→切换companionDecorations[beeId]→保存后显示结果；预览不能直接写持有。F040/F043授予外观与领取回执同事务。

## 数据、事务与事件

F017持有ownedOutfits集合、selectedOutfit及companionDecorations[3]；初始外观0始终可用。沿统一奖励回执恢复持有关系，原型owned函数允许从signin:7和album键推导兼容，生产不能让持有集合和回执产生相互矛盾。OutfitEquipped、CompanionDecorChanged仅驱动展示，不发货币不计任务，重复装备同件为幂等。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 组件接入与生命周期

WardrobePageView配OutfitItemView；CompanionDecorView管每蜂饰物。复用角色呈现组件叠加独立饰物层，若现有资产只有符号装饰，就如实交付可见叠层，不声称有完整角色换装模型。素材沿manifest，禁止重复绘已有成品；快切时按outfitId/beeId检查请求身份。隐藏解除订阅，销毁先释放实例后decRef图像。

继续复用[UIFlow](../../../assets/scripts/app/UIFlow.ts)导航、[GardenAssetStore](../../../assets/scripts/features/garden/resources/GardenAssetStore.ts)登记校验与所属页面资源边界。稳定引用用Inspector强类型绑定，缺项报错；显示订阅、隐藏解除，销毁取消任务与迟到请求，资源addRef/decRef对称。

## 可执行验收

1. 新档仅围巾可装；未持有野餐帽点使用去签到且装备不变。
2. 第3册获云朵胸针后装备，家园、衣柜与冷启动一致。
3. 预览未持有外观再返回：ownedOutfits和selectedOutfit不变。
4. 蜂友29亲密戴饰物拒绝，30可戴取且无数值增益。
5. 小蜜戴饰物→换花花→换回：小蜜原装配保留，不能串给花花。
6. 快速切五件外观并关页：迟到图不覆盖新装备，引用无持续增长。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
