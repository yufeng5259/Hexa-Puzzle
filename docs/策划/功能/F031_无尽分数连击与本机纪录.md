# F031 无尽分数连击与本机纪录

## 规则与流程

放置每格10分；本次消n条线得100n，另加50×n×(n−1)多线奖。连击是连续有效放置均有消除，任一步不消除即归零；非法放置不改变连击。D01尚未确认：策划写“第2次起加25×连击序号”，按第2次序号2可读为+50；原型combo先加一再用25×(combo−1)，第2次实际+25、第3次+50。两种定义都保留，不能暗选一个发布。

规则层先计算本次新增格数与满线数，产生可复核分数明细，再更新run总分；UI播放明细后显示新分数。无尽结算统一比较endlessBest，即使低于发币门槛也可更新本机纪录；保存继续不发“完成一局”。纪录只取max，不因新局、重开或0分结算降低，撤回按F032回滚本局分数但不擅自改已提交纪录。

## 数据、事务与事件

run持有score、combo及计分规则版本，历史best沿F017玩家纪录唯一权威；放置回执记录cellsScore、lineScore、multiLineScore、comboScore以支持诊断。D01确认后固定规则版本与夹具，旧活跃run如何处理须显式迁移。BestChanged与RunSettled由真实结算触发，不让页面展示或预览5000自动解成就。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 可执行验收

1. 放1/3/5格无消线分别得10/30/50，连击归零。
2. 同次两线基础消线200+多线100，三线300+多线300，再独立加放置分。
3. 构造连续两次消线夹具，输出策划+50与原型+25差异，D01签定后锁唯一预期。
4. 一消除→一无消除→再消除，第三步视为新的首消，无连击奖。
5. 结算分数5000再结算4000：本机纪录仍5000；重复结算不重复BestChanged。
6. 非法放置和界面重绘均不改变分数；撤回还原放置前分数与combo。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
