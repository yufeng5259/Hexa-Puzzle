# F026 整园完工唯一奖励

状态：业务未接入。核对日期：2026-10-28。本篇规定后续开发目标，不表示业务或Creator实机验收已完成。

## 规则与流程

资格为当前园building[0..4]均等于5且该园未领奖。每园固定100花蜜、1提示及该园整园合影，一生一次；三园合计300花蜜、3提示、3合影。合影ID为chapter×6+5，与首建五照片构成每园6张。非整园满级拒绝；已领显示已领取或后续入口，不二次发奖，不额外扣出发费。

最后一次升级持久化成功后提示完工；可稍后从家园再开。点击领取时重新取当前园和五栋等级，锁定chapter领取键；将花蜜、提示、合影、领取回执及chapterFinished同次提交。成功后展示实得奖励，非末园进入chapter-next，末园按F028提示当前内容。事务失败保持可重试；关闭/后台后按回执恢复已领状态，不能依赖动画结束写奖。

## 数据、事务与事件

沿F017/F019统一库存，领取键chapter:{chapter}为去重来源；chapterFinished若保留仅为回执的派生缓存，不能与claims相互矛盾。成功事件GardenRewardClaimed携带chapter、receiptId、100、1、photoId；重复命令返回原回执，不重复驱动钱包、照片、解锁或提示飞入。历史园奖励归所属园，不被当前chapter覆盖。

字段为对照原型的目标业务契约，须归入F017/F019/F022约定的统一模型；不能将prototype/app.js或meta.js整段拷入生产，也不能由View直接写库存。

## 组件接入与生命周期

ChapterRewardView只接收资格、奖励快照、提交状态和公开领取端口，复用RewardItemView呈现花蜜与提示；UIFlow维持来源家园。Prefab固定按钮需绑定公开处理方法，业务完成前禁用重复提交，缺绑定立即报错。弹窗关闭取消所属动效与加载，资源先销毁使用实例再对称释放，不取消已提交事务。

继续复用[UIFlow](../../../assets/scripts/app/UIFlow.ts)导航、[GardenAssetStore](../../../assets/scripts/features/garden/resources/GardenAssetStore.ts)登记校验与所属页面资源边界。稳定引用用Inspector强类型绑定，缺项报错；显示订阅、隐藏解除，销毁取消任务与迟到请求，资源addRef/decRef对称。

## 可执行验收

1. 24/25时伪造领取请求：返回未满足，库存、回执、合影全不变。
2. 25/25首次领取：花蜜+100、提示+1、合影+1，同次保存。
3. 双击、重开及冷启动后重放同一领取命令：三项奖励均只到账一次。
4. 在事务保存失败位置注入失败：不能出现只有花蜜或只有回执的半成品。
5. 满级后关闭弹窗，回家园仍可领取；领取后出发按钮才可用。
6. 三园分别领取，三个chapter键独立，合影不串园。

以上为开发后的验收用例，需保留实际操作和Creator预览证据；本次只编写策划，未运行服务、Creator或生产测试，不将静态Prefab检查替代实际业务验收。
